### 1.1 The design premise was wrong, and that mattered

The design doc asserted the Maastricht brochure had `MCID count: 0` and would have no
`/StructParents`. It is **fully tagged**: 60 `MCID`s on page 3, and one visible sentence spans
`MCID`s 5–9 across `Figure > Textbox > P > Span`.

A naive "same MCID" rule therefore split an ordinary paragraph into five uneditable runs and
broke the T25/T26 merges. The implemented rule resolves each `MCID` through
`/StructTreeRoot /ParentTree` to its nearest **block-level** `StructElem` and merges on that:

- page 3, `MCID`s 5–9 → all block `(247, 0)` → the sentence remerges;
- a heading and its body paragraph resolve to different blocks → still separated.

This is the one place where "keep ours" required more work than copying Adobe: a raw-MCID
boundary is Adobe's behaviour, and it is wrong for this document.

### 1.2 Defects found during the stock take

Two bugs were found and fixed while auditing, both of which the existing tests had missed:

1. **`Tc`/`Tw`/`Tz` never reached run advances.** They were applied only inside the `TJ` pen
   walk, so `RawRun.advance` was wrong for any spaced text — which silently corrupts the
   `fits-width` gate. Fixed via `spaced_advance`; regression test added.
2. **Named `/Properties` without `ActualText` raised a false warning.** The writer treated any
   named property bundle as "shared ActualText" and reported divergence. `MCID`-only bundles
   are the normal InDesign shape, so this would have warned on nearly every tagged page. The
   writer now *reads* the named bundle before deciding. Fixture
   `named-property-no-actualtext.pdf` + test added.

A third issue is a **plan correction**, not a code defect: `P2.7-ADOBE-PARITY-PLAN.md` lists
A7 (rotated/skewed text) as "Missing (refused)". It is not refused. Probing a `Tm` of
`[0 1 -1 0 300 100]` returns a run at origin `(300, 100)` with `advance = 114.67` — horizontal
width applied to vertical text. Nothing records the rotation, so a rotated run is *editable but
mis-measured*, and the `fits-width` gate is being evaluated against the wrong axis. That
promotes A7 from "unreachable capability" to **silent wrongness**, which under the programme's
own rule outranks other work.

H0 closed that for rotation carried by `Tm`; **T-7 closed the other half.** H0 read `tm` in
isolation, but the renderer draws with `tm x ctm`, so a page that rotates with `cm` and leaves
`Tm` at the identity (a common producer shape) was still offered as editable with a horizontal
`advance`. Rotation is now read from the composed matrix, with `q`/`Q` saving and restoring the
CTM. A rotation undone by `Q` is not flagged.

**Measured 2026-10-25 — the sentence that stood here was wrong.** It read "the control
fixtures are the point: a translating `cm` stays editable." A translating `cm` is *not*
editable end-to-end. It is not flagged rotated, but it is refused as `run-mismatch`, because
`RawRun::origin` is the text-space pen position and is never composed with the CTM: lopdf
reports `(72, 700)` where PDFium drew the same glyphs at `(172, 750)`, so `pair_run` finds no
box. The same holds for scale (2× and 0.5×) and for an `x`-flip. Four fixtures, all
`rotated == false`, all refused.

What the control test asserted was true but not the claim its name makes: it called the
font gates only, never the pairing path that refuses. It is the third vacuous guard found in
this codebase. The live consequence is that **any** text under a non-identity CTM is falsely
refused — including text inside a Form XObject, which 0.6.0 made editable — with the message
"not addressable in the page's content stream" shown on text the user can read. This is now
P2.7.4's first work item; see `P2.7.4-transform-DESIGN.md` §3.1a.

It also means the earlier statement that the `fits-width` axis error was *closed* for
rotation is right, and the rotation gate is right, but the surrounding surface was never as
covered as it looked.

### 1.2b A green gate can be green for the wrong reason (measured 2026-09-20)

The suite's worst defect class is a test that reports success without testing what its name
says. Three concrete instances, all measured rather than suspected.

1. **The silent skip.** `tests/textedit_gates.rs` begins 33 of its 60 tests with
   `if !pdfium_ready() { return; }`, and `tests/export.rs` 7 of 10. The helper prints a line and
   returns; the test then reports **`ok`, not `ignored`**. Run with
   `PDFIUM_LIBRARY_PATH=/nonexistent`, the suite still says `60 passed; 0 failed; 0 ignored`
   — in 0.21s instead of 4.08s. Every transform gate, every pairing assertion, every end-to-end
   verdict simply does not run, and nothing in the summary distinguishes that from a pass.
   A skipped gate and a satisfied gate are the same colour. `#[ignore]` would at least count.

2. **The name outrunning the body.** `a_run_translated_by_the_graphics_matrix_stays_editable`
   checked only the font gates. It passed while the run was refused end to end as
   `run-mismatch` — the exact bug this phase existed to find, hiding behind a passing test.
   Fixed in item 1. The remaining instance was `an_axis_aligned_run_stays_editable`, which had
   the same shape; it now edits and asserts the edit.

3. **The wrong refusal accepted.** Ten tests assert `.is_err()` without naming the error code,
   gate or message, so they accept any failure — including an unrelated one. These are weaker
   than the two above rather than false: they still fail if the operation succeeds. They are
   listed here rather than mass-edited because tightening them is judgement work per test.

What was checked and found **sound**, so the sweep is not open-ended: the three xobject-refusal
tests (`a_cycle_refuses_with_nested_xobject_and_is_visible`, `depth_nine_refuses_with_nested_xobject`,
`the_cycle_and_depth_fixtures_refuse_visibly_at_the_documented_boundary`) assert on
`resolve_gates` + `font_admissibility` rather than `edit`, which looked like the same defect.
A probe showed `edit` returns the same `TEXT_RUN_NOT_EDITABLE` / `nested-xobject` for both
fixtures, so the layer they test is the layer that decides.

## 3. Deliberate divergences (keep ours)

These are decisions, not gaps. They should survive every future phase.

| # | Ours | Adobe | Why ours stays |
|---|---|---|---|
| D-1 | Merge across a font-resource change when `style_class` matches | never merges across a resource change | Makes the Maastricht bold→roman lines one editable run; safe because `style_match` separates Bold from Roman. |
| D-2 | Hard-refuse overflow, report both widths | silently reflows or overprints | Honest refusal beats layout corruption until P2.7.2 exists. |
| D-3 | Never save over the original | save-over | Destructive writes are unrecoverable. |
| D-4 | Only *rendered* text is editable | maps unrendered text too | Cannot edit what the user cannot see. |
| D-5 | Disclose when `ActualText` diverges | leaves it stale silently | Accessibility regressions must be visible. |
| D-6 | Block-level, not MCID-level, merge boundary | finer boundary | Correct for real InDesign output (one sentence = five MCIDs). |
