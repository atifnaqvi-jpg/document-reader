# P2.7.6 — MECH-B: embedding a bundlable font

> Status: design **FROZEN 2026-09-20** (see §6). The envelope below is the contract the
> implementation and its tests are built against; a change to it needs a new ruling, not an
> edit.
> Scope: non-WinAnsi replacements that MECH-A cannot set. Closes **B8**, and the embedding
> half of **C-4**.
> Target: **0.9.0** — the last phase before reflow. 1.0.0 is P2.8.
> Built on: the A7 skew fix, which is **not** in the published `v0.8.1`. See §7.

## 0. What this phase is, and what it is not

MECH-A converts a `font-subset` refusal into an edit by switching the run to a standard-14
face. That covers Latin-1 and stops there: a replacement containing `—`, `→`, `’` or Greek
still refuses `GLYPHS_NOT_COVERABLE`, because no standard-14 font can set it. Measured
today by `non_winansi_replacement_is_not_coverable` in `tests/textedit_gates.rs`, which
asserts the *absence* of the feature. When this phase lands, that test's subject changes:
the same input must succeed, and a narrower input must still refuse. That inversion is the
acceptance criterion, not a regression.

This phase is **not** "grow the original subset". It never writes to the original font
program (`P2.4-stage2-DESIGN.md` §1, deferred there and still deferred). It embeds a *new*
font, chosen deterministically, as a new resource.

## 1. Preconditions — the envelope

Every claim below is a boundary, not a caveat found later. The suite asserts **within** these
limits and refuses outside them; it never claims universality.

### 1.1 Fonts that are too large to subset

Liberation Sans Regular is 410,820 bytes, Serif 393,692, Mono 319,624 (measured on this
machine, `/usr/share/fonts/truetype/liberation/`). Embedded whole, one non-WinAnsi edit adds
~0.3–0.4 MB and ships the entire glyph repertoire.

The envelope:

| | Value | Why |
|---|---|---|
| Glyph source | the bundled Liberation face for the style-matched family | C-5's ruling; deterministic, no network |
| Subsetting | **required**, not optional | an unsubsetted embed is a ~400 KB regression per edit |
| Subset size bound | asserted per fixture, measured, not guessed | a subset that quietly becomes a full copy must fail a test |
| Retained | the glyphs the replacement needs, plus `.notdef`, `space`, and the metrics for `/W` | `hmtx` for the written codes |

**Out of scope, and refused rather than approximated:** a font whose subset still exceeds
the document-size ceiling; a replacement needing more glyphs than a simple font can address
(that is a CID font, and the Type0 path owns it).

### 1.2 Glyphs outside coverage

Liberation covers Latin, Greek, Cyrillic and a large punctuation repertoire. It does **not**
cover CJK, emoji, or many historical scripts.

Envelope: **coverage is a test, not an assumption.** The embed plan is chosen only when
`ttf-parser` finds a glyph index for every character of the replacement in the bundled face.
Otherwise `GLYPHS_NOT_COVERABLE` stands unchanged — same code, same way out. Tests assert both
sides: a covered non-WinAnsi character embeds; `漢` still refuses.

**Measured 2026-09-20**, because two characters in earlier drafts of this document were wrong
(`tests/font_coverage.rs` now pins all four facts):

| Character | WinAnsi? | In all 12 Liberation faces? | Use |
|---|---|---|---|
| `A`, `EDIT` | yes | — | MECH-A; never proves embedding |
| U+2014 em dash | **yes** (CP1252 0x97) | yes | **not** an embed probe — MECH-A sets it |
| U+0100 Ā | no | yes | cheapest embed probe (one glyph, no layout) |
| U+2192 → | no | yes | covered non-WinAnsi, the design's example |
| U+6F22 漢 | no | **no** | permanent coverage gap (§5 row 3) |

An earlier draft used U+2014 for the embedded case, which would have "proved" embedding with a
standard-14 substitution; another used U+2192 as the *uncovered* case, which every face covers.
Both were invisible while no embed path existed, because "covered but unimplemented" and
"genuinely absent" produced the same refusal.

T11 interaction: **keep-original is checked first and still wins.** A run whose own font
already contains every glyph is never rewritten because a bundle exists.

### 1.3 Unmappable CIDs

Three different things are called "CID" here; only the third is in scope.

1. **`/CIDToGIDMap /Identity`** with a program whose `cmap` reaches every needed glyph — the
   P2.7.5 path. Still `KeepOriginal`; nothing is embedded.
2. **A Type0 run whose `/ToUnicode` and `cmap` both fail for a character.** The replacement
   cannot be expressed as a CID in *that* font.
3. **A run MECH-B replaces.** The embedded face is written as `Type0 / CIDFontType2` with
   `/Identity`, so CID = GID and the subset's glyph IDs are ours to choose. A character with
   no glyph in the subset is not "unmappable" — it is uncovered, and §1.2 applies.

Envelope for (2): if the run is Type0 and the replacement cannot be encoded in the run's own
font, MECH-B substitutes **only with `allow_substitution` consent** (C-4/Q4: substitute only
under explicit consent, never silently). Without consent the result is `SUBSTITUTE_REFUSED`,
not `GLYPHS_NOT_COVERABLE` — the codes say different things and the second would misdescribe
the reason.

**Known limitation, stated up front:** substituting a face for a CID run discards the
original's `/ToUnicode` semantics for glyphs meaningful only in the original font (P2.7.5
§2: the Wingdings `\u{f0e0}` bullet). Reusing such a glyph is not attempted; the whole
replacement is set in the bundled face. If the user reuses a private-use character, coverage
fails and the run refuses. That is the honest direction.

## 2. Mechanism

### 2.1 The plan

`substitute::Plan` gains a third variant:

```rust
Plan::Embed { base_font: String, subset: Subset, note: String }
```

chosen only after `KeepOriginal` has been ruled out. Order stays load-bearing (T11):
keep-original → MECH-A (standard-14, WinAnsi-covered) → MECH-B (bundled face, covered) →
refusal. MECH-A is tried before MECH-B because a standard-14 reference costs no bytes and
every viewer has it.

### 2.2 The written objects

For a simple (non-CID) run the substitute becomes a real font resource:

- `/Type /Font /Subtype /TrueType /BaseFont /<Subset>+<Family>-<Style>` — **not** the
  reserved name; §4.2 states why
- `/FirstChar` / `/LastChar` / `/Widths` from the subset's `hmtx`, in 1000-unit em
- `/FontDescriptor` with `/Flags`, `/FontBBox`, `/ItalicAngle`, `/Ascent`, `/Descent`,
  `/CapHeight`, `/StemV`, and `/FontFile2` = the subset program, `FlateDecode`
- `/Encoding /WinAnsiEncoding` — **only valid when the replacement is actually WinAnsi**;
  otherwise the codes are the subset's chosen codes, written with the `/ToUnicode` below

Every substitute carries a `/ToUnicode` CMap. Without one, copy-paste and search over edited
text return the new bytes as if they were WinAnsi — for U+0100 written as code 0x01 that is
silent corruption of the text layer while rendering correctly. That is the class this
programme treats as worse than a refusal, so the `/ToUnicode` is not optional.

### 2.3 Subsetting

- One pass over the replacement's characters → glyph IDs via `ttf-parser`'s `cmap`.
- Build `loca` + `glyf` for those glyphs (and composite components), `hmtx`, `head`, `hhea`,
  `maxp`, `cmap`, `name`, `post` (v3, no names), `OS/2`.
- Drop `GSUB`, `GPOS`, `GDEF`, `kern`, `DSIG`, `vhea`, and hinting (`fpgm`/`prep`/`cvt`).
  Hinting is dropped deliberately: it is not needed at screen or print sizes and it is
  where subset bugs concentrate.
- A six-letter prefix, deterministic from the content, so two edits in one file do not
  collide and the same input twice yields the same bytes.

**This is not a font compiler.** It never writes a program that renders in our viewer and not
in another. The acceptance test renders the saved file through PDFium *and* re-parses the
subset with `ttf-parser`.

### 2.4 Two refusals, because they have two remedies

**Ruled 2026-09-20.** An earlier draft had a failed subset refuse `GLYPHS_NOT_COVERABLE`, the
same code as "no shipped face has this glyph". That is wrong in the way a refusal that blames
the wrong cause is always wrong: the two facts have different remedies, and only one of them is
in the user's reach.

| Code | Fact | Remedy |
|---|---|---|
| `GLYPHS_NOT_COVERABLE` | No shipped face has the glyph (e.g. `漢`; the bundle is Latin-only) | Choose a different font, shorten the range, or annotate. Permanent within this build. |
| `SUBSET_BUILD_FAILED` | The face **has** the glyph; our subset builder did not produce a valid program | Report it. Retry may succeed. It is our defect. |

Folding them tells a user to "choose a different font" about our own bug, sending them after a
problem they cannot solve. The messages therefore name their own remedy, and
`tests/refusal_split.rs` pins each one — including that a genuine coverage gap returns the
permanent code and **not** the build-failure code.

## 3. Measurement, and which platform checks it

| Assertion | Verified by | Notes |
|---|---|---|
| Subset is smaller than the source face | Linux **and** Windows | byte comparison |
| Subset re-parses and reports exactly the requested glyphs | Linux **and** Windows | `ttf-parser`, no PDFium |
| Edited page renders through PDFium | Linux (PDFium-gated) **and** Windows (render smoke) | Windows runs `--include-ignored` since 0.8.1 |
| `/ToUnicode` round-trips the replacement text | Linux **and** Windows | pure lopdf |
| Width gate uses the **subset's** metrics | Linux **and** Windows | T13 |
| **RSS / cache growth** | **Linux only** | `/proc/self/statm`. If this phase adds a memory assertion, Windows CI passes without checking it, and any report must say so. |

That last row is the standing distinction: a memory claim measured here is a *Linux* claim.

## 4. Licensing (C-5, Q5)

The OFL requires the copyright notice and licence to travel with the font. Three obligations,
all in this phase per Q5:

1. `src-tauri/resources/fonts/LICENSE-Liberation.txt` committed beside the binaries and
   included in the installer payload.
2. An **About / notices** surface naming Liberation and pointing at the licence. Measured,
   not asserted: a test reads the bundled licence and the About component's text, so neither
   can be deleted without a failure.
3. **`src-tauri/resources/fonts/FONT-RECORD.md`** — the audited record: pinned upstream
   version, the package hash it came from, per-face SHA-256, byte count, PostScript name, and
   what each name table actually says. Re-hashed by `tests/font_bundle.rs`, so it cannot drift
   from the shipped bytes.

### 4.1 Provenance: where the binaries come from

Fonts are copied from a **pinned, checksummed package**, with version and SHA-256 per file
recorded in `FONT-RECORD.md`. They are **not** taken from whatever the build machine happens
to have installed.

**Measured correction to this section's first draft.** The draft said "copied from a pinned
upstream release". That is not possible: every upstream GitHub release from 2.1.1 to 2.1.5
has **zero attached assets**, and the source tarball contains only `.sfd` files. Liberation
ships TTFs only as FontForge build output. The bundled bytes therefore come from Debian
`fonts-liberation` **2.1.5-3** (package SHA-256
`3d5c47480067b9615f6bf9b0eda6eefcab9d837af609827015445e8e759b5b8c`), built from upstream tag
commit `4b0192046158`, and are byte-identical to the faces measured for §1.1.

### 4.2 The Reserved Font Name changes the name we write

OFL condition 3: a **Modified Version** may not use the Reserved Font Name as "the primary
font name as presented to the users". The licence defines a Modified Version as a derivative
made by *deleting* components — and **subsetting deletes glyphs**. So every subset MECH-B
writes is a Modified Version, and `/BaseFont /<PREFIX>+LiberationSans` (as §2.2 first drafted
it) would breach that condition.

**Ruled:** the written primary name never contains `Liberation`. The form is
`/<PREFIX>+<Family>-<Style>` with tokens `Sans|Serif|Mono` × `Regular|Bold|Italic|BoldItalic`,
mapping 1:1 onto the twelve faces. The subset's `name` table keeps the copyright and licence
records (IDs 0, 13, 14) and omits the reserved family name. The mapping and the reading behind
it are in `FONT-RECORD.md`; a guard fails if any written token contains the reserved name.

This is not legal advice; it is the reading this project implements, recorded so a later
change has to argue with it rather than silently undo it.

## 5. Acceptance

Replaces the current absence test with a four-way matrix on real bytes:

1. non-WinAnsi, covered, substitution allowed → **succeeds**, subset embedded, renders, text
   round-trips
2. non-WinAnsi, covered, substitution **disallowed** → `SUBSTITUTE_REFUSED`, unchanged
3. non-WinAnsi, **uncovered** (`漢`) → `GLYPHS_NOT_COVERABLE`, unchanged
4. WinAnsi-only → **MECH-A**, and no font program is written (the cheap path stays cheap)

Each new guard is mutation-verified as it is written, with mutations named in the commit
message: coverage check removed, subset-size check removed, `/ToUnicode` omitted, plan order
inverted, licence file removed, About text removed.

## 6. The freeze: four rulings

Ruled 2026-09-20. Each names the evidence it rests on. R1 and R4 are measured in this
repository; R2 and R3 restate programme rulings that already bind this phase.

### R1 — Which faces ship: the **distinct-class rule**

**Ruled:** ship a face only if it owns a `style_class` that no other shipped face owns. Apply
the rule to the whole set, not by name, so it survives faces being added.

**Measured, not assumed.** `style_match` was driven with each face's own name-table
family/subfamily *and* with its filename, over all 16 installed Liberation faces:

- The 12 non-Narrow faces map onto exactly 12 distinct classes — a bijection, so every
  shipped face is selectable and no two share a class.
- All 4 Sans Narrow faces collapse onto the Sans classes (`SansNarrow-Regular` →
  `Helvetica`, `-Bold` → `Helvetica-Bold`, …). `style_match` can never address them, so
  they cannot be selected; shipping them would be 4 × ~120 KB of dead payload.
- **Narrow is therefore R1's first application, not a special case.** The measured set
  leaves nothing else to exclude.

| class | face | | class | face |
|---|---|---|---|---|
| Helvetica | Sans-Regular | | Times-Roman | Serif-Regular |
| Helvetica-Bold | Sans-Bold | | Times-Bold | Serif-Bold |
| Helvetica-Oblique | Sans-Italic | | Times-Italic | Serif-Italic |
| Helvetica-BoldOblique | Sans-BoldItalic | | Times-BoldItalic | Serif-BoldItalic |
| Courier | Mono-Regular | | Courier-Bold | Mono-Bold |
| Courier-Oblique | Mono-Italic | | Courier-BoldOblique | Mono-BoldItalic |

**Shipped set: 12 faces, 4,360,440 bytes (4.16 MB)** — measured on this machine, the 16
installed files totalling 4,843,104 B minus the four Narrow faces.

### R2 — The written shape: `/ToUnicode` on every substitute; `Type0` only for Type0 runs

**Ruled:** a simple (non-CID) run is written as a simple `/TrueType` font with chosen codes
plus a `/ToUnicode`; a run that was already `Type0` is written as `Type0 / CIDFontType2`.

`/ToUnicode` is **not optional** on either. Without it, copy-paste and search over edited text
return the new bytes as if they were WinAnsi — for U+0100 written as code `0x01` the page
renders correctly while the text layer is silently wrong. That is the failure class this
programme treats as worse than a refusal (§2.2).

`/Encoding /WinAnsiEncoding` is written **only** when the replacement really is WinAnsi;
otherwise the codes are ours and the `/ToUnicode` is the only honest mapping. Writing WinAnsi
over our own codes would be a false claim in the file.

**Why not `Type0` everywhere:** it is uniform but changes the write path for runs that were
simple, and P2.7.5 measured that the simple path already round-trips. The test pins which
shape each fixture produces, so the choice cannot drift silently.

### R3 — Substitution needs explicit consent, and refusal codes stay distinct

**Ruled** (C-4/Q4, restated because MECH-B is where it is enforced): substitution happens
only under the explicit `allow_substitution` consent, **never silently**.

The three outcomes keep distinct codes, because they send the reader to different remedies:

| situation | code |
|---|---|
| no consent to substitute | `SUBSTITUTE_REFUSED` |
| consented, but the bundled face cannot cover a character | `GLYPHS_NOT_COVERABLE` |
| consented and covered | success, with a note naming the substitute (T10) |

Collapsing the first two into one code was rejected: "you said no" and "the font cannot do
it" are not the same problem, and only one of them is fixed by saying yes.

### R4 — T11 is checked first and is not bypassable by the embed path

**Ruled:** the plan order is `KeepOriginal` → MECH-A → MECH-B → refusal, and the first step is
absolute. A run whose own font already contains every glyph is **never** rewritten because a
bundle exists. The cheap path also stays cheap: a WinAnsi-only replacement takes MECH-A and
writes no font program at all.

The first guard this phase writes asserts the order, and it is written **before** the embed
path exists, so the path cannot be introduced with the order already bypassed. §5's fourth
matrix row is the same invariant stated as acceptance.

### The A7 question — which refusals change because skew is now writable

Asked at freeze. **Measured by running every committed transform fixture through
`describe_runs` at this commit:**

| fixture | verdict before A7 | after A7 |
|---|---|---|
| `unrotated_text` | editable, 114.67pt | unchanged |
| `rotated_text` (`Tm`) | editable, 114.67pt | unchanged |
| `rotated_by_graphics_matrix` | editable, 114.67pt | unchanged |
| `scaled_by_graphics_matrix(2.0)` | editable, 229.34pt | unchanged |
| `scaled_by_graphics_matrix(0.5)` | editable, 57.34pt | unchanged |
| `translated_by_graphics_matrix` | editable, 114.67pt | unchanged |
| `mirrored_by_graphics_matrix` | `mirrored-text` | `mirrored-text` |

**No committed fixture changes from refused to editable.** Every named fixture was already
writable at 0.8.1; A7 changed only *skew* and *anisotropic* cases, and none of those had a
committed fixture. Those were measured through a throwaway probe and are covered by new
guards, not by a fixture that changed behaviour.

Two consequences, both recorded rather than left implicit:

1. **The measured defect had no fixture.** A bug that refused every sheared run shipped in
   0.8.1 because the fixture set contained `Tm` rotation and `cm` rotation but no `cm` shear.
   The new guards use their own shear fixtures; that gap is why they exist.
2. **RELEASE-NOTES must still name the change.** "No fixture changed" is not "no behaviour
   changed" — a user with a skewed page saw a refusal in 0.8.1 and will not see one in 0.9.0.
   That is a user-visible widening of what can be edited, and it belongs in the notes.

### Platform claims

R1's byte counts are Linux measurements of the installed files. They are inputs to a
**pinned upstream archive** (§4), not to whatever the runner image ships; the installer must
not depend on the runner's font directory.

## 7. Provenance, and what 0.9.0 is built on

### The tree contains fixes that the published `v0.8.1` does not

Measured at freeze: `git merge-base --is-ancestor 6685208 v0.8.1` is false. The A7 skew fix
and the CI floor change are in `HEAD` only; the published `v0.8.1` was built from `1b88c80`,
which predates them.

That is legal — 0.8.1 is published history and is not rewritten — but it means **the next
installer must not be labelled 0.8.1**. An auto-updater comparing semver would see the same
version and decline to offer a build with a real fix in it. 0.9.0 is therefore the next
version *for the tree as a whole*, and it contains what 0.8.1 never had: the A7 skew fix, the
CI floor corrections, the frozen design, and the bundled font payload.

**Ruled 2026-09-20: all carriers moved to 0.9.0 in one commit.** They previously read
`0.8.1`, which made `the_shipped_version_has_release_notes` pass by matching a number the
tree could not honour — a guard green on a coincidence. The notes section records why A7 was
folded into this release instead of shipping 0.8.2 (B-3's *commit* boundary is kept; only its
release boundary is folded).

The release notes say this in the 0.9.0 section rather than leaving a reader to diff tags.

### The 0.9.0 provenance rule

Carried forward from 0.8.1's discipline:

1. **Tag the exact commit the workflow ran on.** The tag is created on the green commit, not
   on a later merge or a rebuild of a different tree. `git tag v0.9.0 <sha>` where `<sha>` is
   the commit the gate ran against.
2. **Record the workflow run ID in the release and in the plan row.** The 0.8.1 row records a
   run ID, a commit SHA, an installer filename, its SHA-256 and the artifact ID. The 0.9.0 row
   records the same five facts, and the release body names the run.
3. **A rebuild is a new run ID, not a silent replacement.** If the installer is rebuilt from a
   different commit, the recorded SHA-256 no longer describes the asset, and the release must
   say so rather than keep a stale hash.

The gate for this phase is therefore: `--include-ignored` green on the release commit, a
Windows installer hand-confirmed **before** the tag exists, and the plan row carrying all five
facts before it is marked `[x]` (Q9: a phase is `[~]` until the installer is hand-confirmed).

### Hand-confirmation happens before tagging

An earlier revision of this section said the installer "from that tagged run" must be
hand-confirmed. That is unsatisfiable, and 0.9.0 was tagged under it anyway. A tag run
publishes as well as builds, so the sentence asked for a human to confirm a build that does
not exist until the release is already public -- and publication cannot be withdrawn if the
confirmation then fails. The order below is the one that works, and is the one 0.9.0 actually
followed:

1. **Build only.** `workflow_dispatch` on the release commit publishes nothing; it uploads
   `document-reader-windows-installer` as a workflow artifact.
2. **Hand-confirm that artifact.** This is Q9's hand-test, and it is the only step that reads
   a running application.
3. **Tag the same commit.** The tag run rebuilds and republishes the same tree. Its asset is
   expected to differ from the hand-tested artifact by the embedded NSIS build timestamp and
   by nothing else; a difference in file *contents* other than that timestamp means the tag
   run did not build the confirmed tree, and the release is wrong.

Rule 1 in *The 0.9.0 provenance rule* above ("tag the exact commit the workflow ran on") is
unchanged by this: the tag still points at the commit, and the hand-confirmed build still
comes from that commit. What this section fixes is the *order* of confirmation and tagging,
which the published rule left ambiguous enough to be read backwards.

For 0.9.0: dispatch `41154631220` built and uploaded the installer from `6caaedd`; that
artifact (10,321,346 bytes) was hand-confirmed; `v0.9.0` was created on `6caaedd` afterwards.
The tag run `41273111581` republished the tree as a 10,340,606-byte asset.
