## 2. What the §5 sweep proves, and what it does not

The sweep fills all three spellings the design names — `/Yes`, `/On`, `/yes` — plus the
real-producer file, and asserts three things per row: the value persisted (I-F1), the saved
file begins with the source bytes verbatim (D-F4), and the source on disk is untouched.

The tamper negative is the part worth reading. The committed LibreOffice file has `/V /Yes`
and an `/AP /N` key of `/yes` — measured, not assumed: the test asserts both halves before it
fills anything. A writer that took the legal state set from `/V` would write an `/AS` naming
a stream that does not exist. The test requires the refusal to name `yes`, which is only
possible if the legal set came from `/AP /N`, and it then fills `yes` successfully so the
refusal is a distinction rather than a blanket rejection.

**It does not prove a viewer draws the tick.** That is §3.

Mutation-verified for this unit, each mutation placed in `editor/forms.rs`:

| Mutation | Killed by |
|---|---|
| take the legal state set from `/V` as well as `/AP /N` | `the_tamper_negative_refuses_the_spelling_the_appearance_does_not_draw` |
| make the writer rewrite instead of append | six tests, including the sweep |
| write the old value, leaving `/V` alone (W3's prescribed mutation) | `every_field_type_reads_back_the_value_that_was_written`, `a_second_fill_keeps_the_first_fills_value`, `a_fill_sets_need_appearances_on_the_saved_file` |

One mutation **survives** and is recorded rather than papered over: removing the sweep's own
byte-prefix assertion changes no test outcome, because
`a_fill_preserves_the_source_bytes_verbatim_as_its_first_revision` asserts the same property.
The sweep's assertion is a restatement, not a second guard. That is acceptable in a test whose
job is to be readable, but it must not be counted twice as evidence.

## 3. W4 and W6 — both closed 2026-11-15

This section said both were missing. They were, and they are not now. The original text is kept
struck through rather than deleted, because these were real absences found by looking at the
tree, and the record should show that rather than imply they never existed.

~~**The pixel test the design names does not exist.**~~ **Landed in `63832a2`.** It renders the
`/On` fixture at 4x and counts dark pixels inside the widget rectangle: **0 before the fill, 212
after**. `/On` is the case that matters because it carries no `/NeedAppearances` for a viewer to
shortcut through, so the tick can only come from the appearance stream our writer selected. The
first attempt rendered at 1.0 and measured 10 vs 13 — a three-pixel margin that would pass on an
anti-aliasing difference — so the scale went up rather than the assertion going down.
Mutation-verified twice: dropping the `/AS` write (0 vs 0, nothing drawn at all), and writing
`/AS /Off` so the value reads back as requested while no tick is drawn. The second is precisely
the failure no assertion on the dictionary can see, which is why the design demanded pixels.

~~**The certification gate is not called from the fill path.**~~ **Landed in `0d09809`.**
`fill_and_save` calls `editpolicy::check(level, EditKind::FormFill)` before validation or any
write. The test asserts `P=2` and `P=3` produce a filled file, `P=1` refuses with
`CERTIFICATION_REFUSES_EDIT` naming its level, and a `P=1` document still *opens and lists its
fields* — reading is not filling, and a gate that made a certified document unopenable would be a
worse bug than the one it fixed. It proves the ordering rather than asserting it: a `P=1` refusal
must leave no file, so the gate cannot have run after the write. Mutation-verified twice: removing
the check, and passing `EditKind::Signature` so `P=1` is permitted.

One consequence to carry forward: the `GOVERNED` table in `tests/certification_gate.rs` still does
not list a fill command, because there is still no such command — the fill path is reached through
the library, not through `src/commands/`. When a command is added it must be added there too, and
that guard will not remind anyone.

## 4. W7 landed 2026-11-15 (`4833897`)

*(Revised 2026-11-15. This section read "W7 is not started" until the unit landed the same day; the
correction is here rather than in a new section because the section is the record of that claim.)*

XFDF form-data import/export is in `src-tauri/src/editor/xfdf.rs` as the `form_data` submodule:
`FieldValue`, `FormDataReport`, `parse`, `write`/`export`, `values`, `refuse_non_xfdf`. FDF is
refused **by content** (`%FDF-`), not by extension, and the refusal names XFDF as what is supported
(`AppError` variant in `src-tauri/src/model/mod.rs`).

Three real bugs were caught by writing the tests before believing the code, all in the parser:

- `trim_text(true)`, copied from the annotation parser directly above, ate the whitespace around
  entities — `"a & b < c"` read back as `"a  b  c"`. The sibling module had already recorded this
  exact trap in a comment.
- Nameless `<field>` elements were never counted, because the close branch keyed on the name being
  present — losing precisely the case the count exists for. Now a separate `in_field` flag.
- Entities arrive as `Event::GeneralRef`, not as text, so `&` vanished entirely (`"abc"` for
  `"a & b < c"`). Reuses the parent module's `reference_char()` rather than a second spelling.

Five mutations, all caught: no FDF refusal; dropping nameless fields silently; reinstating
`trim_text(true)`; export writing an empty value; the `GeneralRef` arm.

The round-trip test is the claim W7 exists to make and is *not* a parser test: it fills `given` on a
synthetic form, reads the value back **out of the saved file**, exports it to XFDF, parses it,
and fills a **fresh copy of the original** — so the value can only have arrived through the
interchange. Asserting the parser alone would pass while export and the fill path disagreed about
field names.

## 6. The question this report raised, and how it answered itself

*Written as a halt; retained because the reasoning still governs W8.*

The question was whether P3.3 closes without the pixel test. The answer did not need a ruling:
`provider::PdfProvider::render_page_at` already existed and already returned an encoded image, and
`image` 0.25 was already a dependency, so the test the design asked for was about forty lines.
**It was implemented rather than deferred as debt.** The release note can therefore describe the
checkbox tick and point at a test that demonstrates it — the only condition that made writing that
line honest.

That resolves the ordering the halt was protecting: notes first, then bump, because a bump that
lands before its notes is the ordering the design forbids. **W8 is unblocked.**

**What the pixel test does not prove, and the notes must not claim:** it proves our writer selects
the right appearance stream and that PDFium draws it. It does not prove Acrobat or Preview agree,
and it does not cover the LibreOffice file's `/NeedAppearances true` path, where a viewer ignores
our `/AP` and regenerates its own. That path is covered only as far as §2's value-and-key handling
goes.

### What to try, in order

The point of a hand-test is to look for what a test suite cannot see, so these are ordered by how
much the automated checks already cover — do the least-covered ones first.

1. **A form the app did not make.** Take a real PDF form (a government or tax form you already have;
   nothing needs uploading). Open it, type in a text field, save, reopen. The synthetic fixtures are
   ours on both sides; this is the one case where they are not.
2. **A checkbox, in the app and then in a second viewer.** Tick one, save, reopen in the app — then
   open the saved file in a browser's PDF viewer or Acrobat. The pixel test proves *our* renderer
   draws the tick; this is the only check that someone else's does.
3. **A form the app refuses.** Try to fill a read-only field, and a checkbox with a value that is
   not one of its states. Each should refuse and name the field, and no file should appear beside
   the original. A refusal that writes a half-filled file is the failure mode this guards.
4. **XFDF round trip.** Fill something, export XFDF, close, reopen the *original*, import. Values
   should land. Then rename any `.fdf` you have to `.xfdf` and import it — it must be refused by
   name, not accepted and mangled.
5. **A certified document.** If you have one signed as "no changes allowed", filling must refuse and
   name the level. Reading must still work.
6. **Save-over behaviour.** Confirm a fill writes a copy and leaves the original alone, and that the
   dialog says which (P2-D2 discipline). This is the one place where a wrong default destroys a
   file rather than annoying someone.

Anything that fails, note what you clicked and what it said. A hand-test failure is more valuable
than a green gate, because it is the only signal from outside our own code.
