## 0. The inclusion rule

The standing instruction is: take Adobe's functionality, but **where our implementation is
better, keep ours**. That rule needs a test, or it degenerates into preference. So a
capability is adopted from Adobe only when *all three* hold:

1. **It closes a refusal or a silence we have today.** Not "Adobe has it" — a user-visible
   gap in our matrix below.
2. **Adopting it does not weaken a safety invariant.** Every P2.4/P2.6 gate
   (`fits-width`, `encoding-round-trip`, `run-mismatch`, `selection-range`) survives. If an
   Adobe behaviour would require dropping one, we keep ours and the capability is deferred.
3. **Either we have no equivalent, or ours is measurably worse on the acceptance fixture.**

Where ours is measurably better, the divergence is **recorded as a deliberate difference**,
not quietly dropped. There are already two:

| Divergence | Ours | Adobe | Verdict |
|---|---|---|---|
| Cross-resource merging | merges when `style_class` matches (T26) | never merges across a resource change | **Keep ours.** It is why the Maastricht bold→roman lines are one editable run. Safe because `style_match` separates Times-Bold from Times-Roman. |
| Width enforcement | hard-refuse, report both widths (`fits-width`) | silently reflows or overprints | **Keep ours** until reflow exists (P2.8). Refusing is honest; overprinting corrupts. |

Sequencing is by *refusals users actually hit*, not by Adobe's menu order. A2/A3/A9 first
because a wrong merge boundary and a stale ActualText are silent wrongness — worse than a
refusal. Reflow last because it is the largest and the only one that can corrupt layout.

**Ordering ruled 2026-09-20 (B-3):** A7 rotation is a **separate hotfix commit** before the next

## 3. Cross-cutting rules for every phase

- **No gate is weakened.** A phase adds capabilities behind existing gates; if it must
  relax a gate, that is a design decision recorded in the phase doc, not a side effect.
- **Real-bytes acceptance.** Each phase commits a fixture derived from the user's actual
  documents where one exists. Synthetic fixtures have repeatedly hidden defects (0.4.1
  through 0.4.4 all passed synthetic tests while failing the brochure).
- **Silent wrongness outranks refusals.** A phase that makes the app refuse *less* but
  *incorrectly* is a regression even if more edits succeed.
- **Structure is additive.** P2.7.1 must behave identically on untagged PDFs and must not
  regress a single gate on tagged ones. The Maastricht brochure was assumed untagged when this
  plan was written; it is in fact fully tagged (60 `MCIDs` on page 3, five of them across one
  visible sentence), which is why the boundary is the resolved **block** structure element and
  not the raw `MCID` — see the correction in `P2.7.1-mcid-DESIGN.md` §5.

### Invariants that now govern reflow (C-2, ruled)

1. **"Never split a run" is relaxed for reflow only.** Line-level reflow cannot work without
   crossing run boundaries; splits are recoverable by a cleanup pass. The relaxation is scoped to
   the reflow path and must not leak into ordinary edits.
2. **"One-edit-one-undo" stays absolute.** Implemented as a **grouped transaction** across all
   content-stream mutations in the reflow, not a single operand swap. A user-visible multi-step
   undo is itself a silent-wrongness failure.
3. **`fits-width` stays absolute.** Hard validation: fail the operation rather than commit an
   overflowing line. Reflow does not relax the gate; it changes what the user can do before
   hitting it.

### Named future features carved out of the deferred inventory (B-1)

Tracked separately so they are not absorbed later as ordinary parity items:

| Feature | Invariant stated up front |
|---|---|
| **Redaction** | A redaction that appears to work while leaving recoverable text beneath it is the worst outcome in the product. Failure to remove underlying text is a **data-leak bug**, not a rendering bug. |
| **Signatures** | The invariant is not "detect that an edit touched covered content" but **"the signature is definitively invalid once content it covers changes."** A signature that does not invalidate on edit is a **legal-reliance bug**. |

**U-3 — Page operations record no undo.** `rotatePage` and `deletePages` reach the UI
through `runDerived` (`src/components/EditorPane.tsx`), which takes a `label`, discards it
(`void label`) and never calls `push`. So the two page operations are

Found while closing U-1; not re-opened there because it is coverage, not grouping.
Acceptance test first: a new test, *a page rotation is one undo and undo restores the previous

text edit and content-stream text, and none covers a page op.
Note the shape: the fix needs a *before* snapshot of the page tree, which the page
commands do not currently return, so this is not a one-line change.
