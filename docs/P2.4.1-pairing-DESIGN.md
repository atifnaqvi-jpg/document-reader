# P2.4.1 — Run pairing by geometry + fragment merging (DESIGN, frozen pending sign-off)

Version 1.0 — 2026-10-11. Owner: GLM 5.3 Flash (design). Implementation after sign-off: Deepseek 4.1 Flash.
**Correctness hotfix** between Stage 2 (shipped, `3606763`) and Stage 3. Extends `P2.4-stage2-DESIGN.md`;
amends nothing frozen. Stage gate applies: this doc alone, then code.

## 0. Problem statement (reported on 0.4.0, verified in code)

Real PDFs (Word/PowerPoint-style emission) fragment text into tiny operands — `Tj` per kerning
group or per-glyph `TJ` arrays. The picker pairs lopdf runs (one string operand each) with
PDFium runs (whole words/lines) by **exact text equality, in order**. Fragment ≠ word, so
pairing fails for most runs; `describe_runs` (`textedit.rs:267`) then refuses them `run-mismatch`.
User-visible: only occasional runs editable, everything else refused — on every page.
Substitution itself (MECH-A) works; **the joining strategy is the defect.**

Root cause is design, not accident: `textlocate.rs` deliberately refuses PDFium's reconstructed
text as identity (correct — bytes must come from the operand path), but the *pairing* was left
text-based and brittle. The gate matrix had no fragmented-TJ fixture, so tests could not catch it.

## 1. Fix in one line

Pair runs **by geometry** (position on the page), which is segmentation-independent, and
— per user ruling 2026-10-11 — **merge adjacent same-font fragments into word-ish runs**
for the picker. Write path stays lopdf-only (T1) and revalidates per-operand (T4 unchanged).

## 2. New invariants

| # | Invariant | Rationale |
|----|-----------|-----------|
| **T17** | **Pairing is geometric; text equality is only a tiebreaker.** A lopdf run pairs with a PDFium run whose rect contains (or is nearest to) the run's origin, within tolerance. Two sides may segment differently; origins and overlap still agree. | Segmented strings must still pair — the 0.4.0 defect. |
| **T18** | **Merged runs disclose and rewrite atomically.** A merged run shows its joined text, names fragment count and font; its write replaces the first operand's bytes with the new text and empties the remaining fragment operands **in one lopdf pass** — never two saves, never PDFium. | Single writer (T1); partial rewrites would corrupt the word. |
| **T19** | **Merge only when unambiguous:** same `font_key`, same `Tf` size, shared baseline (y within 0.5 pt), and horizontal gap ≤ `0.25 × font_size` between fragment ends. Never merge across fonts, sizes, or line breaks. | A merged run must be *encodable* with one font/encoding and must read as one word. |
| **T20** | **Every existing gate gates per-fragment before merge.** Any refused fragment (font gates, round-trip) refuses the merged run with that gate; the merger never bypasses a refusal. | No stage weakens a safety gate (cf. T14). |
| **T21** | **Pairing failures are visible, not silent:** an unpaired-but-editable run keeps its refusal with its *reason* (unpaired ⇒ `run-mismatch` only when no rect plausibly contains it; paired-with-low-confidence flagged in diagnostics). Exact semantics: see §3 step 4. | The 0.4.0 bug produced *correct-looking* refusals; diagnostics must expose pairing, not hide it. |

## 3. The pairing algorithm

1. **lopdf origins.** `textlocate.rs` already walks the decoded content sequentially. Track the
   text matrix through `Tm` (set), `Td/TD` (translate), `T*` (line feed + TL), `TL` (leading),
   and the font size from `Tf`. Each `RawRun` gains `origin: (x, y)` (the current matrix's
   translation at the time the string operand shows) and `font_size`.
   **Not** a full CTM implementation: only translation and size are needed for pairing;
   skewed/sheared text is out of scope for measurement (Stage 3 territory) but origins still
   resolve via the translation components.
2. **PDFium side already has rects** (`runmetrics::PdfiumRun`). Pair = rect contains origin, or
   nearest rect when ambiguous (tie-break: leftmost, then text equality).
3. **Confidence.** Pair is *strong* when origin ∈ rect and the rect's baseline y matches within
   0.5 pt; *weak* otherwise (nearest-only). Weak pairs still get geometry (that is the point),
   but are marked in the run's diagnostics for the write-time re-check.
4. **Unpaired editable runs** — no rect plausibly contains the origin: refuse `run-mismatch`
   as today, but the refusal message now *names why*: "no matching rendered box on the page".
5. **Width gate (O1/T13) is unchanged:** old width = the paired rect's advance width (sum of
   fragments for merged runs); tolerance `max(0.5 pt, 1% of old)`; report both widths; suggest
   annotation. Metrics source rules (AFM vs hmtx) as in Stage 2 §4.

## 4. Merge mechanics (user ruling: merge = YES, affects write path)

**Picker model.** After pairing, group consecutive paired fragments on one baseline into
`MergedRun { fragments: Vec<RawRun>, text, font, size, rect }`. UI lists merged runs first;
a user can still expand to pick a single fragment (picker shows both levels). Merged text is
shown verbatim; T10-style disclosure names the merge: *"combines 3 fragments of F1"*.

**Write path (lopdf only).**
1. Re-validate every fragment's operand path and signature (T4 unchanged) — mismatch ⇒
   `RunMismatch`.
2. Encode the replacement text in the fragment group's single font (gates already proved the
   font; MECH-A substitution applies per merged-run font, same as Stage 2 §4 step 3–4).
3. Mutate: first fragment's string operand ← new bytes; other `Tj` strings in the group ←
   empty; `TJ` arrays keep their positioning numbers untouched (kerning stays; empties show
   nothing). One decode→mutate→encode pass, one save.
4. FTS5 re-extract + re-populate after the write (Stage-1 T6/R5 rule), because the page's
   extracted text changes even where glyphs vanish into empties.
5. Undo (T7/T16): one edit = one undo entry; restore re-writes the original bytes back into
   their original operand paths.

**Refusal naming:** a merged run whose replacement is wider refuses per O1 with both widths
(measured across the merged rect). New code `MERGE_*` only if a distinct message is needed —
preferred: reuse `RunMismatch` + prose.

## 6. Boundaries

- **No reflow** (Stage 3): empties carve holes in kerned arrays; that is today's honest
  behaviour, carried into merged runs.
- **No CID/Identity-H re-encoding**, no MECH-B bundling, no forms/OCR/etc. (O3).
- Windows-only, as always.
- **Version/installer:** land as **0.4.1**; rebuild installer for the user's re-test — this
  hotfix is meaningless until they can touch it.
