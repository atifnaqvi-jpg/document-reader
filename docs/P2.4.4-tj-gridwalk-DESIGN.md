# P2.4.4 — T24: Grid-walk the TJ array (fragment spans from the rendered parent object)

Status: **DESIGN** · Parent-derived, ground-truth driven (the real Maastricht PDF was probed end-to-end in the dev sandbox: lopdf runs, PDFium objects, and the full `describe_runs` pipeline).
Version target: **0.4.4**

## 1. Root cause (proven, not inferred)

For a subset font with no in-file metrics (ABCDEE+Monaco class), the lopdf TJ walker
(`textlocate.rs`) advances the pen by `fragment_advance` = **0.5 em per glyph**. Monaco is a
**0.6 em** face. Inside `[(5)-7( )8(m)-7(o)-7(n)-7(th )24(U)…(ence )] TJ`, per-fragment
origins drift **left of the rendered page cumulatively ~1.5 pt/char** (lopdf `ence ` origin
293.5 vs PDFium true ≈299.5).

Causal chain, each step verified by probe output:

1. `locate_span` anchors the char-grid search on the drifting origin → long fragments match
   the **wrong grid chars** (`"ence "`'s x-window overlaps grid `a`, ` `, `S`, `c`).
2. Measured gaps/spans become garbage → `mergeable` fails at some seam → `group_runs`
   yields **singletons** for the 22-element line.
3. The picker offers the **last** singleton (`ence `); its width quota is a mislocated span
   (36 pt from wrong chars) with `box_suspicious=true`, `Weak` confidence — yet admissible,
   because admissibility does not consult confidence.

Case history this explains: short operands (`course`, 4 elements) drift only ~4 pt — still
inside their own word window, so they merged ("combines 4 fragments"); the long line never
merged in 0.4.1/0.4.2/0.4.3. Synthetic fixtures passed because narrow glyphs make 0.5 em ≈
correct, so the walker never diverged. T17/T22/T23 were correctly *designed*; they were fed a
drifting anchor.

## 2. T24 — the rendered parent object is the coordinate oracle

**Invariant:** a fragment's true span is the union of the **parent PDFium text object's grid
chars assigned to that fragment** — located by character alignment inside the object's own
char window, never by the approximated pen.

Algorithm:

1. For each lopdf fragment group belonging to one PDFium text object (same font/size/
   baseline; the object is already known from pairing), locate the object's **char window**:
   the contiguous grid-index range whose non-generated chars spell the object's text,
   searched within the object's own box (baseline band + x-range) using the existing
   `locate` machinery.
2. Walk the window left → right, assigning **consecutive non-generated chars** to the lopdf
   fragments in order of the fragments' cumulative decoded-text lengths. Both sides decode
   through the same ToUnicode CMap, so lengths and identity agree; PDFium-generated chars
   (synthesised spaces, CR/LF) are skipped, never assigned.
3. Fragment span = union of its assigned chars' advance boxes. Any char-identity mismatch →
   that fragment falls back to today's `locate_span` path (safe direction, no behaviour
   change for the mismatched fragment).
4. `Pair.span` for fragments inside an object becomes the T24 span. `measured_gap`,
   `group_span`, `resolve_quota` consume it **unchanged** — predicates are not touched. With
   exact spans, the Sci→ence gap measures ≈0 and the 22-element chain merges into one run.

Non-goals (unchanged): no new font parsing (T24 removes the *dependency* on font metrics for
span/merge; the §1 metrics findings remain recorded in `docs/P2.4.3-FINDINGS.md`), no CID
rewidthing, no reflow, no OCR, Windows-first as always.

## 3. Acceptance tests

- **T24-A (memorialising fixture — real bytes):** the user's Maastricht brochure as a test
  fixture (trimmed page fixture `real-maastricht-line.pdf`, or the full 385 KB file if the
  trim is lossy), page index 1: `describe_runs` yields **one** editable run
  `"5 month University level Data Science "` with `fragment_count=23`, width = the true
  rendered span (~277 pt), `box_suspicious=false`, admissible; a narrower replacement passes
  gate (d); a wider one hard-refuses quoting both measured widths.
- **T24-B (synthetic regression):** a 22+-element TJ of **wide glyphs (0.6 em advance)** in
  a metrics-less subset font — reproduces the ≥6 pt drift on any architecture; previously
  fragmented, now one merged run.
- **T24-C (generated-char alignment):** a TJ with a kern seam large enough for PDFium to
  synthesise a space mid-word; fragments still align one-to-one with their rendered chars.
- **All existing gates stay green** (P2.4.1's 24 gate tests, P2.4.2's chain-break fixtures,
  P2.4.3's T23 suite): T24 changes the span *source*, never a predicate.
