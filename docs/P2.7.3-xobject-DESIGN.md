# P2.7.3 — Form XObjects (DESIGN, frozen)

Status: **FROZEN v1.0** · 2026-09-20 · Item 3 of `docs/P2.7-TEXT-EDITING-PARITY-PLAN.md`
Version target: **0.6.0**
Rulings applied: **B-7** (copy-on-write), **Q1/Q2/Q3** (2026-09-20), **Q6** (grouped inverse)

## 0. Why this is next, and what it is not

Matrix row **A6 — "Edit inside Form XObjects" — is the last *unreachable text* gap.** Today
`locate_runs` decodes only the page's own content stream. Text drawn by a Form XObject is
absent from the picker: not refused, not explained, simply not there. That is the worst
outcome this programme recognises — the user sees text, clicks it, and the app behaves as if
the page were blank.

This phase makes that text reachable and editable **without changing any text it was not
asked to change**. It is not a rendering phase: no transform maths, no colour spaces, no
nested-resource inheritance beyond what §4 requires.

## 1. Scope

**In:**

- Walk `Do` operators whose operand names a `/XObject` of `/Subtype /Form`, and locate the
  text runs inside that form's decoded content stream.
- Address such a run by `(page, xobject_path, op_index, operand_path)`, where `xobject_path`
  is the list of **resource names** followed to reach it (`["X1"]`, or `["X1", "X2"]` for a
  nested form).
- **Copy-on-write per draw** (Q2): the draw the user clicked is cloned; every other draw of
  the same form, on this page or any other, is untouched.
- Give the clone a private `/Resources` when — and only when — the edit touches it (Q3).
- Refuse nesting deeper than the cap, and cycles, **visibly** (Q1).
- Record the inverse as one grouped transaction, so one edit is one undo (Q6).

**Out (explicit):**

- `/Subtype /Image` XObjects: they hold samples, not text.
- `Do` used for anything other than a form (an image, an unresolvable reference).
- Transforms inside the form (`/Matrix`, `cm`). The composed transform is **not** applied to
  `origin`/`advance`; a run that the existing `rotated` detection would flag is refused
  exactly as on a page. Form `/Matrix` folding is P2.7.4.
- CID/Identity-H text inside a form — refused by the existing `simple-font` gate, unchanged.
- Editing the form's `/BBox`, `/Matrix`, `/OC`, or any key other than `/Resources` and
  `/Contents`.
- Optimising away a form that becomes redundant after a copy.

## 2. The two rulings that shape the data model

### 2.1 Per draw, not per page (Q2)

The edit unit for an XObject run is the **draw**. Editing the instance the user clicked must
change that instance and nothing else.

Consequence: an XObject reachable from two `Do` operators is copied **at the outermost draw
on the page**, and the page's `Do` operand is repointed at the copy. Copying at an inner level
would leave the outer form shared, so the copy would still be reached by the original outer
form's other draws — the edit would leak into them.

For a nested path `["X1", "X2"]` the copy happens **at every level along the path, outermost
first**: copy `X1`, repoint the page's `Do`; then copy `X2` *inside the copy of* `X1`, and
repoint the copy's `Do`. This is unconditional rather than "only when shared", because
determining share counts correctly for arbitrary object graphs is more failure-prone than
copying a form that is usually a few kilobytes, and the path is bounded by §5's cap.

*Rejected: copy per page.* It is cheaper (one copy however many draws) but produces a
silently wrong result for a user who clicked one instance — "I edited the header and the
footer changed too" is not a disclosure problem, it is an incorrect edit. Storage
duplication is harmless; an unintended visible change is not.

### 2.2 The address is a resource name, never an object id

`Document::renumber_objects()` reassigns every object id in sorted order starting at 1, and
`edit_page_text` / `revert_page_text` both call it before saving. **An `ObjectId` recorded in
an address or an inverse is therefore invalid the moment it is written to disk.** The undo
opens the saved file and must still find the object, so the address uses resource names
(`X1`), which live in a resource dictionary and are rewritten only when we deliberately
rewrite them.

This is not a stylistic choice; recording an `ObjectId` here would produce an inverse that
resolves to a different object. The same reasoning is why `PropertyClone` already stores the
*name* alongside the object id.

## 3. Address and API shape

```rust
/// One step of descent into a page's Form XObjects, by resource name.
pub struct XObjectStep {
    /// The `/XObject` entry's name in the enclosing resource dictionary (`X1`).
    pub name: Vec<u8>,
    /// Index of the `Do` operation in the enclosing content stream that drew it.
    pub op_index: usize,
}
```

`RunId` gains `xobject_path: Vec<XObjectStep>` (`#[serde(default)]`, so every existing
payload and test keeps its meaning: empty means the page's own stream). `PageTextRun` mirrors
it. The TS `TextRunId` gains the same optional field.

The `op_index` in a step is **not** used to resolve the object (the name is); it is what the
undo needs to repoint the `Do`, and it must be re-validated before use — see §7.

## 4. Discovery: descending, and what "visible refusal" requires

`locate_runs` becomes a recursive walk. For each `Do` naming a `/Form` XObject it resolves:

1. the object reference from the enclosing `/Resources /XObject`;
2. the stream, refusing if it is not a form;
3. the **form's own** `/Resources`, falling back to the enclosing resource dictionary for
   keys the form does not define (inheritance is per-key, not whole-dictionary).

Runs found at any level are returned with the path that reached them. A run's `font_key` is
resolved against the resources **in force at that level**, not the page's, or a form using
`/F9` would be decoded through the page's unrelated `/F1`. This is the same class of bug that
`T-3b` fixed for named `/Properties`: *resolve the slot, then read.*

### 4.1 Depth limit and cycles (Q1)

Depth is the number of XObject steps: page = 0, a form drawn by the page = 1.

- A path whose length would exceed **8** is not descended. `Gate::NestedXObject` is emitted.
- A form already on the current path is a cycle and is not descended. `Gate::NestedXObject`.
- A `Do` that names an image, or a reference that does not resolve to a form, is skipped —
  there is no text in it, so it is not a refusal.

**Interpretation recorded for correction.** Q1 says both "walk one level" and "refuse at
depth > 8". Those cannot both be literal: a one-level walk never reaches depth 2, so the cap
would be dead code, and — decisively — stopping at one level leaves text in nested forms
invisible to the picker, which is the exact silent failure the same answer forbids. The
implementation therefore descends level by level and enforces the cap, which is the only
reading under which both sentences do work. If the intent was instead "nested forms refuse at
the first level", the cap in §4.1 becomes `1` and nothing else in this design changes.

### 4.2 Making the refusal visible

A depth or cycle refusal has no run to attach to — the text is precisely what we refused to
walk. Returning no runs would reproduce the invisibility this gate exists to prevent. So each
undescendable `Do` contributes a **placeholder run**:

- `id` = the `Do` operation's own address (`op_index` of the `Do`, `operand_path: [0]`,
  `xobject_path` of the enclosing level);
- `text` = `/X1` (the resource name), `operator` = `Do`;
- `admissibility.gate` = `nested-xobject`, with a message naming depth or cycle and the way
  out (annotate instead);
- `rect`/`width` = `None`.

The placeholder is never editable, so the write path cannot receive it; `RunId` for it points
at a name operand, which would fail every write validation anyway. Gate precedence must put
`nested-xobject` **ahead of** `run-mismatch`, or the placeholder's missing PDFium box would
mask the real reason — the same precedence bug that H0 avoided for `rotated-text`.

## 5. Copy-on-write mechanics

For an editable run at path `[X1, …]` on page `p`:

1. **Clone each level, outermost first.** For each step `(name, do_index)`:
   clone the form's stream object, install the clone in the *enclosing* level's
   `/XObject` dictionary under a fresh name (`X1_edit1`, mirroring `fresh_property_name`),
   and set the `Do` operand at `do_index` to the clone's name.
   Enclosing level = the page's resources for the first step, the previous clone otherwise.
2. **Give the clone a private `/Resources` only if the edit will modify it** — i.e. font
   substitution (`ensure_substitute_resource`) or a named-`/Properties` clone. Then clone the
   `/Resources` dictionary (or its indirect object) for the copy and rewrite the copy's
   `/Resources` reference. Sharing it would recreate B-7 one level down.
3. **Edit the clone's decoded content stream** with the existing `apply_merged` path, reading
   its runs through the resources resolved in step 1. No new write code: the operand
   substitution, font swap and `ActualText` rewrite are the page path's.
4. **Write the clone's content** with `change_content_stream(clone_id, …)` — **not**
   `change_page_content`, which targets a *page* dictionary. Verified behaviour (probe,
   2026-09-20): `change_page_content` on a stream object returns
   `Err(ObjectType { expected: "Dictionary", found: "Stream" })`, and on a dictionary whose
   `/Contents` is neither a reference nor an array it returns **`Ok(())` having written
   nothing**. So it is wrong here twice over: it does not address the object we mean, and its
   silent arm can report success without writing.

### 5.1 Is the enclosing `/Resources` shared?

Adding a fresh name to the page's `/Resources /XObject` mutates that dictionary. If two pages
share one indirect `/Resources` object, both now carry the clone name — harmless for rendering
(no other content stream names it) but still a write to a shared object. Consistent with
T-3b, the page's resources are copied before the name is added **when the resources object is
referenced by more than one page**. The share check is a reference count over page
dictionaries, not a heuristic.

## 6. Gates

| Gate | When | Precedence |
|---|---|---|
| `nested-xobject` (new) | path would exceed depth 8, or a cycle | before `run-mismatch`; after nothing |
| `rotated-text` | existing, now also from a form's composed matrix | before font gates (unchanged) |
| `simple-font`, `encoding-round-trip` | existing, resolved from the form's resources | unchanged |
| `fits-width` | existing, unchanged measurement | unchanged |
| `run-mismatch` | placeholder with no box, or content changed under the picker | unchanged |

`nested-xobject` is a *traversal* refusal, so it precedes every content gate. No existing gate
is relaxed, and none may be: an XObject run is admissible only if it would be admissible
drawn directly on the page.

## 7. Inverse and undo (Q6)

The grouped-inverse machinery **already exists** and must be reused, not rebuilt:

- `ContentOperation.also` is the group: a merged run's sibling writes are already recorded
  there, and `revert` replays every member in one pass;
- `font_swap.also` and `property_clone` are further legs of the same transaction;
- the frontend pushes exactly one entry per edit (`EditorProvider.push`), so one edit is one
  visible undo today.

P2.7.3 adds two legs to that existing tree rather than a new mechanism:

```rust
pub struct XObjectClone {
    /// Enclosing level: empty for the page, else the path to the container.
    pub parent_path: Vec<XObjectStep>,
    /// The `Do` the edit repointed, and the names before/after.
    pub do_index: usize,
    pub old_name: Vec<u8>,
    pub new_name: Vec<u8>,
    /// The clone object, removed on undo so no orphan accumulates.
    pub clone_object: ObjectId,
    /// The private `/Resources` installed on the clone, if the edit made one.
    pub cloned_resources: Option<ObjectId>,
}
```

`ContentOperation` gains `xobject_clones: Vec<XObjectClone>` (empty at page level) and
`xobject_path: Vec<XObjectStep>` for the operand address. Undo, in one pass over the saved
file:

1. re-validate each `Do`: operator is `Do`, its operand is the `new_name` this edit wrote,
   and the enclosing level still resolves. A mismatch refuses (`run-mismatch`) rather than
   repointing a `Do` the user did not edit;
2. restore the operand bytes, font name, `ActualText` clone and `BDC` name exactly as today;
3. repoint each `Do` to `old_name`;
4. remove each clone's fresh name from its enclosing `/XObject` dictionary and drop the clone
   object (and the cloned `/Resources`), so edit-then-undo leaves no orphan — the same rule
   `revert` already applies to `PropertyClone`.

*`ObjectId` in the inverse is safe here* because the inverse is applied to the file it was
produced from, before that file is renumbered again: `revert_page_text` loads the file, applies
the inverse, then renumbers. This is the one place an id is legitimate, and it is why §2.2's
rule is about *addresses*, not about the clone record.

|---|---|

| `editing_one_draw_leaves_the_other_draw_byte_identical` | **Q2.** Red if the copy is replaced by an in-place edit: decoded `/X1` changes on the second draw too |
| `editing_a_shared_form_on_one_page_leaves_the_other_page_untouched` | copy is page-private |
| `a_nested_run_is_editable_and_only_its_draw_changes` | per-level copy, §2.1 |
| `a_cycle_refuses_with_nested_xobject_and_is_visible` | Q1 cycle; placeholder present, gate set |
| `depth_nine_refuses_with_nested_xobject` | Q1 cap; depth 8 editable, 9 refused |
| `the_nested_xobject_gate_outranks_run_mismatch` | precedence, §4.2 |
| `a_substituted_font_gets_a_private_resources_dict` | **Q3.** Red if the clone keeps the shared dict |
| `undo_restores_the_do_and_drops_the_clone` | grouped inverse; no orphan object after save+reload |
| `undo_leaves_the_other_draw_untouched` | inverse is draw-scoped |

Non-vacuity is proved by mutation, as in T-3/T-7: replacing the clone step with a direct
in-place edit must fail the two "leaves untouched" tests, and deleting the `Do` restore must
fail the two undo tests.

## 9. Rollout

- 0.6.0. No existing address changes meaning: an empty `xobject_path` is the page, so every
  0.5.0 payload and every un-migrated inverse still works.
- The UI needs no new control: runs inside forms arrive through the same
  `get_page_text_runs`, and `nested-xobject` renders through the existing gate display.
- `docs/P2.7-TEXT-EDITING-PARITY-PLAN.md` row A6 moves `Missing → Have` when the gate is
  green **and** the installer is confirmed (Q9).

None. Q1–Q3 and Q6 are ruled and recorded in §F. The one interpretation requiring the
