# P2.4 Design — Content-Stream Text Editing (v1.0)

Status: **frozen 2026-10-04 by user instruction**. Amends `DECISIONS.md` §8 and
`P2-DESIGN.md` D1/D3 (records below). Does not re-litigate other frozen
constraints (Tauri 2 + Rust, local-first, PDFium, SQLite, Windows-only v1).

## 0. Goal and authority

The user reversed the "no touching text" constraint and made in-place text
editing the active requirement. The app therefore gains a real **write path to
page content streams**. The user set explicit guardrails (recorded verbatim in
§1); this document turns them into a buildable design.

**Staged delivery — each stage performs REAL editing (no overlay):**

| Stage | Delivers | Status |
|-------|----------|--------|
| 1 | Constrained in-place edit when the font is simple + fully recoverable and the text run is addressable; explicit refusal otherwise | **P2.4 scope** |
| 2 | Font embedding + subsetting (unlocks most real PDFs) | future phase |
| 3 | Line reflow / re-positioning | future phase |

Option "A" (annotation-only corrections) was explicitly rejected as the
deliverable. Option "C" (full free-text) is the destination but must not be
attempted in one push.

## 1. User decisions (frozen, quoted from instruction)

- **Q1** — "no touching text" is REVERSED; §8 text-editing exclusion is
  superseded. Annotations non-goal language superseded by P2 design.
- **Q3 — WRITER POLICY: lopdf is the ONLY writer.** PDFium renders/extracts
  and NEVER writes. Editing modules produce mutations; lopdf persists them.
  Two writers = corruption = user data loss. Fixed up front.
- **Q4** — Encrypted PDFs default **read-only**. No automatic decryption, no
  re-encryption, ever. An explicit "Decrypt a copy" action is the only path to
  an editable copy.
- **Q2** — Stage 1 refusal must be explicit, never silent.

## 2. Verified capability facts (crate sources, 0.8.37 / 0.45.0)

| # | Fact | Consequence |
|---|------|-------------|
| F1 | lopdf `Stream::decode_content()` and `Document::get_and_decode_page_content(page_id)` are public; `Content::encode()` re-serialises operations. | The full parse → mutate → re-encode loop is reachable in pure lopdf. **No PDFium write path involved.** |
| F2 | `Document::get_page_content(page_id)` **concatenates all content streams** with `\n` separators. | Rewriting an edited page collapses its stream array into one stream. Legal (PDF spec allows it), acceptable under D2 copy semantics. |
| F3 | `Document::get_page_content_with_limit(page_id, max)` bounds decompressed size. | Decompression-bomb guard; text edit must use the bounded reader and refuse beyond a cap. |
| F4 | lopdf content parser handles inline images (`BI…ID…EI`) round-trippably. | Parsed-and-rewritten pages do not corrupt inline images. |
| F5 | `Document::get_page_fonts(page_id)` and `Encoding::{bytes_to_string,string_to_bytes}` (`decode_text`/`encode_text`) are public. | Run-level string↔Unicode round-trip through the *document's own* font encoding is public API. |
| F6 | PDFium side is READ-ONLY for editing: `PdfPageTextObject::set_text`/`as_text_object_mut` exist but mutate PDFium's model, and `Pdfium::save_*` (`FPDF_SaveAsCopy`) is a second writer — **forbidden by Q3.** | PDFium's role: extract text/positions/fonts/widths for the picker and width maths. Never persist. |
| F7 | lopdf `LoadOptions::with_password` decrypts on load; `Document::encrypt()` exists but Q4 forbids encryption mutation. Removing the trailer `/Encrypt` entry yields an unencrypted save. | "Decrypt a copy" = load with password → strip `/Encrypt` → save new file → verify round-trip. |
| F8 | pdfium-render surfaces `PdfiumInternalError::PasswordError` vs `SecurityError` distinctly. | New `AppError` codes can distinguish "wrong password" from "rights-limited". |
| F9 | Simple-font evidence: fixture `sample.pdf` is `/Type1 /Helvetica /WinAnsiEncoding` — the *best case*. | Fixtures alone can't validate refusal paths; §6 fixture matrix is mandatory. |

## 3. Frozen decisions (P2.4)

| ID | Decision | Rationale |
|----|----------|-----------|
| **T1** | **lopdf is the only writer** (Q3, restated as a checkable rule): CI greps that `src-tauri/src/**` contains no `pdfium .save_to_*`/`FPDF_SaveAsCopy` reference outside `lopdf_write.rs`. Currently satisfied (verified 2026-10-04). | Two writers = silent corruption; user data loss. |
| **T2** | **Edit pipeline:** `decode (F1) → locate run → mutate Operation operands → re-encode → replace that stream object → lopdf save (D2 temp-file discipline)`. Page is addressed by 0-based index; run by (op-index, operand-index) recovered at pick time, re-validated before write. | Single seam (P2-D1); keeps undo trivial: the inverse mutation is the old bytes. |
| **T3** | **Stage-1 admissibility gates (ALL must pass, else explicit refusal):** (a) simple font — Type1/TrueType, NOT CID/Identity-H; (b) encoding round-trips: `encode_text(decode_text(bytes)) == bytes` for the target run; (c) font not subset-flagged (`ABCDEF+` prefix or partial-glyph evidence); (d) replacement fits the run's advance width at its font size (widths from PDFium metrics, read-only) — metric-rounding tolerance allowed: refuse only when `new_width > old_width + max(0.5 pt, 1% of old_width)` (O1, confirmed: HARD-REFUSE, "equal-or-shorter allowed" NOT adopted); the refusal message must report BOTH measured widths and suggest the annotation tool; (e) decoded content under the F3 size cap. | Refusal message names the violated gate and suggests the closest alternative (e.g. add a text annotation). Silent mangling is the enemy. |
| **T4** | **Pick-time truth vs write-time truth:** the run the user taps is resolved by PDFium extraction for UX, but the *authoritative* targeting is the lopdf-parsed run matched by decoded text + ordinal within the page. If the two disagree at write time → refuse (T3 gate f: mismatch). | PDFium reconstruction (ToUnicode, ligatures) must never be assumed equal to content bytes. |
| **T5** | **Undo/redo (extends P2-D7):** a text edit pushes an inverse `ContentOperation { stream_id, op_index, old Operand, new Operand }`. Session-scoped, coalesced per commit, memory cap unchanged. | Mutations are small; inverse is exact. No re-hydration problem. |
| **T6** | **Derived-state invalidation (extends P2-D6/D11):** successful text edit invalidates render cache by path+page, re-extracts page text, re-populates FTS5 for that document, and emits the annotation-style change event renamed generically (`document://changed`). | Search/annotations must never disagree with visible content. |
| **T7** | **Encrypted default = read-only (Q4):** documents failing to open without a password open with a calm banner ("password-protected — opened read-only"); ALL edit commands refuse with `ENCRYPTED_READ_ONLY` code. Never prompt automatically; prompt only when the user opens the file or requests an action that needs it. | No password fishing loops; no surprises. |
| **T8** | **"Decrypt a copy" (Q4 explicit path):** menu action → password prompt → confirmation dialog stating protection will be removed on the NEW copy only → load via lopdf with password → strip trailer `/Encrypt` → save to D2 path labelled with ` (unprotected)` suffix → byte-verify (open without password, page count + text hash match) → on ANY failure delete the temp and refuse. Original file byte-identical on disk. **Collision guard (O2, confirmed):** if the target path already exists, never silently overwrite — use numbered suffixes `"{stem} (unprotected 2).pdf"`, `… (unprotected 3).pdf`, … (first free index wins). Decrypted copy is then editable under Stage 1–3 rules like any other document. | Protection removal is deliberate, labelled, and never automatic; no user data is ever clobbered. |
| **T9** | **No re-encryption, ever (Q4):** T8 never calls `Document::encrypt`; lopdf never performs encryption mutation. | Highest risk, lowest benefit; rejected permanently. |
| **T10** | **Password handling:** in-memory for the session only; never on disk, never in SQLite, never in events/logs. Cleared on document close and app exit (not merely dropped). | Local-first does not mean password-at-rest. |
| **T11** | **Stage gate:** Stage 2 (embedding/subsetting) and Stage 3 (reflow) are separate future phases, each with their own frozen-design doc. No partial or hidden implementations of either inside P2.4. | Deliberate staging per user instruction. |

## 4. Modules

```
/src-tauri/src/editor/
  textedit.rs      NEW  Stage-1 pipeline: decode, locate, gate, mutate, re-encode
  textlocate.rs    NEW  run matching (T4): decode text via font Encoding, ordinals
  commands/mod.rs  +3 commands: get_page_text_runs, edit_page_text, decrypt_copy
/src/api/invoke.ts +types  thin wrappers, same error convention
Frontend: text-run picker in the viewer (reuse hit-testing geometry from
annotations); refusal toast quoting the violated T3 gate; encrypted banner
(T7); Decrypt-a-copy flow (T8).
```

`get_page_text_runs(page)` returns runs with: id (op/operand index), text,
rect, font name, size, admissibility verdict (gate list), so the UI can grey
out inadmissible runs *before* the user commits to an edit. Refusal reasons are
pre-computed, not discovered after typing.

## 5. Error surface

New `AppError` variants and codes:

| Variant | Code | When |
|---------|------|------|
| `EncryptedReadOnly` | `ENCRYPTED_READ_ONLY` | edit attempted on protected doc (T7) |
| `WrongPassword` | `WRONG_PASSWORD` | F7/`FPDF_ERR_PASSWORD` mapped honestly |
| `TextRunNotEditable(String)` | `TEXT_RUN_NOT_EDITABLE` | T3 gate failure; string names the gate |
| `TextRunMismatch` | `TEXT_RUN_MISMATCH` | T4 pick/write disagreement |
| `ContentTooLarge` | `CONTENT_TOO_LARGE` | F3 cap exceeded |

Frontend `ToAppError` mapping gets these codes; no string-matching.

## 6. Test fixture matrix (mandatory before coding)

The existing `sample.pdf` only exercises the best case (F9). Stage-1 code may
not be tested solely against it. Generate fixtures with lopdf itself (public
API, no new deps):

1. `simple-winansi.pdf` — Type1 Helvetica (exists) → happy path.
2. `simple-embedded-subset.pdf` — TrueType with `Subset` flag evidence → gate (c) refusal.
3. `cid-identity.pdf` — CID font, Identity-H → gate (a) refusal.
4. `roundtrip-fail.pdf` — font whose encoding fails bytes→Unicode→bytes → gate (b) refusal.
5. `too-wide.pdf` — run whose replacement exceeds advance width → gate (d) refusal.
6. `encrypted-aes.pdf` — produced via `Document::encrypt` on a decrypted source → T7/T8 paths.
7. `multi-stream-page.pdf` — page content in several streams (F2 collapse path).
8. `bomb.pdf` — massively-compressed content stream → F3 cap refusal.

Each fixture is a committed, tiny, version-controlled file with a comment in
the fixture dir README stating which gates it exercises. If a needed fixture
cannot be produced with public API, that stage gate is NOT implemented — the
limitation is documented instead.

## 7. Out of scope (unchanged or newly frozen)

Form-filling, true redaction, OCR/EPUB/DOCX, cloud sync, digital signatures,
PDF creation, merging — unchanged or newly confirmed OUT (O3, confirmed
2026-10-04: item-6 wish-list items were NOT promoted by lifting item 1; only
in-place text editing became a requirement; Stage 1–3 target existing text in
existing PDFs, Windows only).
Stage 2/3 capabilities (font embedding/subsetting, reflow) — deferred to their
own phases (T11), not "hidden features" in this one.
Re-encryption — permanently rejected (Q4/T9).

## 8. Open items — RESOLVED 2026-10-04 (all confirmed by user)

- **O1 (width policy):** HARD-REFUSE on overflow. Tolerance for metric
  rounding: refuse only when `new_width > old_width + max(0.5 pt, 1% of
  old_width)`. Refusal reports both measured widths and suggests annotation.
  "Equal-or-shorter allowed" explicitly NOT adopted. → folded into T3(d).
- **O2 (decrypted-copy naming):** `"{stem} (unprotected).pdf"` confirmed, with
  collision guard: never silently overwrite — numbered suffixes
  `… (unprotected 2).pdf`, `… (3)`, first free index wins. → folded into T8.
- **O3 (other non-goals):** OCR, form-filling, digital signatures, PDF
  creation/merging, macOS/Linux all REMAIN OUT. → folded into §7.
- **Fixtures:** synthetic 8-fixture matrix via lopdf public API is the GATE
  (§6). Real-world PDFs are supplementary validation only; nothing waits on
  them.
