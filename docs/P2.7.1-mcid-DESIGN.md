# P2.7.1 — MCID boundaries and ActualText preservation (DESIGN, frozen)

Status: **FROZEN v1.1** · 2026-09-20 · Item 1 of `docs/P2.7-TEXT-EDITING-PARITY-PLAN.md`
Version target: **0.5.0**

> **v1.1 changes (2026-09-20), recorded rather than silently rewritten:** the implementation
> outgrew several v1.0 claims. §1 no longer says we ignore `StructTreeRoot` (we do use
> `/ParentTree` for the block boundary); `Ts` is listed as **not** tracked (it was never
> implemented); §8's test names now match the tests that exist; §10's encoding claim is
> corrected to name Latin-1 and the outstanding PDFDocEncoding gap; and §6 gains a
> copy-on-write requirement for named `/Properties` (ruling B-7).

## 0. Why this is first

Our merge boundary is a heuristic: same `style_class`, same baseline, gap inside a window.
Acrobat's boundary is the document's own structure (`MCID`). Two failure modes follow from
the difference, and both are *silent* — worse than a refusal:

1. **Wrong merge.** Two same-style fragments in different tagged units (a table cell and the
   cell beside it, two short paragraphs, a caption and the figure label under it) satisfy
   every geometric predicate and become one editable run. The user edits "Revenue 2024" and
   the write lands across a cell boundary.
2. **Stale `ActualText`.** A tagged PDF may wrap text in
   `/Span <</ActualText <FEFF…>>> BDC`. We currently edit the operand bytes and leave the
   `ActualText` string untouched, so the rendered text and the semantic text diverge. That is
   an accessibility regression *and* it makes Acrobat's own copy/paste disagree with the page.

Both are invisible in the UI today. That outranks every feature in the programme.

## 1. Scope

**In:**

- Parse marked-content sequences while walking the page content stream: `BDC` / `BMC` /
  `EMC`, with the property dictionary or named resource giving `MCID`.
- Record each run's marked-content context: an ordered stack of `(tag, mcid, actual_text)`
  entries, outermost first.
- **Stop merges across an `MCID` boundary**: two adjacent fragments with different innermost
  `MCID` are separate runs, whatever their geometry says.
- **Preserve `ActualText` on edit**: when the head fragment's context carries an `ActualText`
  and the edit only replaces that context's text, rewrite the `ActualText` to match the
  replacement.
- **Track `Tc` / `Tw` / `Tz`** in the pen walk. Small, and it rides with the same walker;
  before P2.7.1 `fragment_advance` ignored all three, so a metrics-less font with character
  spacing drifted. **`Ts` is *not* tracked in v1.0/v1.1** and folds into 0.5.0 per ruling B-5
  (see §7); it does not move the pen horizontally.

**Out (explicit):**

- **Validating** the structure tree, or writing to it. We read the marked-content stream for
  boundaries and actual text, and we *resolve* `MCID` through `/StructTreeRoot /ParentTree` to
  find the block element (§5). A malformed or absent tree must not block an edit the stream
  supports — it degrades to the `Untyped` fallback.
- Rewriting `StructTreeRoot` `/K` ordering, `/Alt`, `/Lang`. Only `ActualText` on the edited
  span.
- Inserting `BDC`/`EMC` wrappers around text we split. We never split a run into more
  `MCID`s.
- Reflow (P2.7.2), XObjects (P2.7.3), transforms (P2.7.4), CID (P2.7.5), embedding (P2.7.6).

## 2. Invariants

| # | Invariant | Rationale |
|---|---|---|
| **T27** | **Tagged structure is advisory for boundaries, never for safety.** An `MCID` boundary can only *prevent* a merge. It can never make an otherwise-inadmissible run editable. | A wrong/legacy `MCID` must not widen what the write path accepts. |
| **T28** | **Untagged pages are unchanged, and tagged pages keep their existing merges at block granularity.** With no `BDC` carrying an `MCID`, every predicate, span and group is exactly as in 0.4.5. On a tagged page, the boundary is the resolved **block** element, not the `MCID`, so a paragraph split into inline spans still merges. The Maastricht brochure (60 `MCIDs` on page 3, five of them across one sentence) must pass T25/T26 untouched. | No regression by construction; the real fixture proves it. |
| **T29** | **A boundary never splits within one text-showing operation.** `MCID`s change only at `BDC`/`EMC`, which cannot occur *inside* a `TJ` array. If a malformed stream suggests otherwise, the operation's own fragments stay together and the context is that of the operation's start. | One edit is one operation; splitting it would require rewriting the array. |
| **T30** | **`ActualText` is rewritten only when it is the direct `ActualText` of the run's innermost `BDC` and that context contains no other operand.** Otherwise the edit proceeds and the run is reported with `actual_text_preserved: false` so the UI can warn. | Rewriting a shared `ActualText` would silently change text outside the edit. |
| **T31** | **The `BDC`/`EMC` stack is validated by depth, not by tag name.** `BMC` (no properties, no `MCID`) still pushes a depth. An unbalanced `EMC` at depth 0 is ignored; an unclosed `BDC` at page end does not fail the page. | Real producers emit unbalanced sequences; refusing the page would make files uneditable that render fine. |

## 3. Data model

```rust
/// One entry of the marked-content stack at a run's start.
pub struct MarkedContent {
    /// The tag (`Span`, `P`, `Artifact`, …). Never used for admissibility (T27).
    pub tag: String,
    /// The `MCID` if this sequence declared one.
    pub mcid: Option<i64>,
    /// The decoded `/ActualText`, when present and decodable.
    pub actual_text: Option<String>,
}
```

`RawRun` gains `marked_content: Vec<MarkedContent>` (outermost first, empty when untagged)
and `merge_scope() -> Option<MergeScope>`, where

```rust
pub enum MergeScope {
    Block(ObjectId),      // resolved block-level structure element: the real boundary
    Untyped(Option<i64>), // unresolved: fall back to the finer raw MCID
}
```

`PageTextRun` gains `mcid: Option<i64>` and
`actual_text_preserved: bool` (default `true`, so an untagged run serialises exactly as
today).

## 4. Parsing

`textlocate::locate_runs` already iterates `content.operations` once. Add a stack:

- `BDC` — operands are `(tag, properties)`. Properties is a dictionary (inline) or a name
  resolving through `/Properties` in the page resources. Push. `MCID` is
  `properties.get(b"MCID")` as an integer; `ActualText` is a string, decoded as UTF-16BE
  when it starts `FE FF`, else PDFDocEncoding — **which v1.1 does not yet decode correctly;
  see §10.**
- `BMC` — push a tag with no `MCID`.
- `EMC` — pop; ignore at depth 0 (T31).
- Every other operation: the stack is unchanged.

The stack is snapshotted onto each `RawRun` at the point the operand is emitted, so a `TJ`
array straddling a `BDC` (malformed) keeps the context it started in (T29).

`/Properties` lookup uses `document.get_page_resources(page_id)`, which we already call for
fonts; no new traversal.

## 5. Merge rule

> **Correction (2026-09-20, during implementation).** The first draft of this section said to
> compare `innermost_mcid` directly, and §2/T28 claimed the Maastricht brochure had no `MCIDs`.
> Both were wrong, and the second one was the dangerous error: the brochure is **fully
> tagged** (60 `MCIDs` on page 3), and one visual sentence is spread across `MCID`s 5, 6, 7, 8
> and 9. Comparing raw `MCID`s split that sentence into five runs and broke T25/T26 — 4 of the
> 45 gate assertions. An `MCID` is a *content-item* granularity, not a paragraph.

The boundary is the run's **block**, not its `MCID`:

```
same_tagged_unit = head.merge_scope() == next.merge_scope()
```

`merge_scope()` resolves the innermost `MCID` through the page's `/ParentTree` to a structure
element and walks `/P` up to the nearest **block-level** role (`P`, `H1`–`H6`, `LI`, `TD`,
`TH`, `Figure`, `Caption`, … — see `is_block_role`). That element is the paragraph or cell a
reader would name, and merging within it is correct no matter how many inline `Span`s the
producer wrapped.

When the structure tree is absent, malformed, or does not cover the `MCID`, the scope falls
back to `MergeScope::Untyped(mcid)`, which is *finer* than a block. That direction is
deliberate: an unresolved boundary may refuse a merge a reader would allow, and never allows
one that crosses a cell.

Two runs with **no** `MCID` on either side compare equal (`None == None`) — untagged pages
unchanged (T28). A tagged run never merges with an untagged one (`Some(_) != None`), which is
the conservative direction.

Verified against the real brochure: `MCID`s 5/6/7 on page 3 all resolve to struct element
`247 0 R` (the `P` that owns them), so the sentence remerges; the `H1` at `MCID 6` on an
earlier page resolves to its own element, so a heading never joins the body text after it.

## 6. ActualText rewrite

On a successful edit whose replacement is written into the head operand:

1. If the head's innermost `BDC` declared `ActualText` **and** no other operand in the page
   shares that `BDC` range (T30), rewrite that string object to the replacement, encoded as
   `FE FF` + UTF-16BE.
2. If it declared `ActualText` under a **named** `/Properties` entry, do **not** mutate the
   shared dictionary. Per ruling B-7 the write path uses **copy-on-write**: clone the entry
   under a fresh key (e.g. `/P0_edit1`), point this `BDC` at the clone, and rewrite the clone.
   The original stays untouched for every other sequence that names it. If the clone cannot be
   created (no room in the resource dictionary, unresolvable reference), fall back to
   `actual_text_preserved = false` and disclose. Never edit a shared object in place, and never
   silently diverge.
3. If there is no `ActualText`, do nothing (the overwhelmingly common case).

The rewrite is part of the same `apply_merged` / `apply_text` pass, so one undo restores both
the operand and the `ActualText`.

## 7. Pen-walk additions

`TextMatrixWalk` gains `char_spacing`, `word_spacing`, `horizontal_scale`. `Tc`/`Tw`/`Tz`
set them and `BT` resets them to 0/0/100 (ISO 32000-1 9.4.1). `fragment_advance` gains
`Tc × chars + Tw × spaces` and multiplies by `Tz/100`.

**`Ts` (text rise) is not implemented in v1.1.** It does not change the horizontal advance, so
it cannot affect `fits-width`; it affects the recorded baseline, and therefore pairing. Ruling
B-5 folds it into 0.5.0, so it must be added before the version bump or explicitly listed as a
known gap in the release notes.

The PDFium grid remains the oracle wherever it has an answer; this only removes drift from the
metrics-less and fallback paths.

## 10. Risks

| Risk | Mitigation |
|---|---|
| `MCID` present but meaningless (producer emitted one per line) | Boundaries only *prevent* merges; worst case is more, smaller runs — the 0.4.3 picker behaviour. Never a wrong write. |
| **`ActualText` encoding correctness** | `decode_text_string` currently falls back to `byte as char`, which is **Latin-1**, not PDFDocEncoding. Bytes `0x80`–`0x9F` differ from the standard, so we can read one character and write another while reporting `actual_text_preserved: true`. **Must be fixed before 0.5.0** (ruling B-6): implement the PDFDocEncoding table, or refuse to rewrite when such bytes are present. |
| Performance on long streams | One stack push/pop per operation, already a single pass. No new traversal. |
