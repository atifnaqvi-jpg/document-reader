# P2.7.5 — CID / Type0 in-place editing, and honest font copy

> Status: design, frozen for implementation. Closes open question **C-4**.
> Scope: (2) native CID/Type0 editing + (3) accurate refusals and toggle copy.
> Target: v0.8.0.

## 1. The reported failure

v0.6.0 refuses to edit `Each hour of lecture – 2-3 hours of study` on page 4 of the
Maastricht brochure with the `simple-font` gate. Measurements taken with the app's own
locator (`examples/probe_lines.rs`, `probe_encode.rs`) show the line is not one font:

| fragment | font | subtype | encoding | text |
|---|---|---|---|---|
| op 488 | `/F2` | Type0 | Identity-H | `•` |
| op 504 | `/F3` | TrueType | WinAnsi | `Each hour of lecture ` |
| op 520 | `/F7` | Type0 | Identity-H | `\u{f0e0}` (Wingdings bullet) |
| op 536–568 | `/F3` | TrueType | WinAnsi | `2-3 hours of study` |

The picker merges all of them into one run because `mergeable()` compares
`style_class` — and `style_match("ABCDEE+Monaco")`, `style_match("ArialMT")` and
`style_match("ABCDEE+Wingdings-Regular")` **all** return `Helvetica`. The merged run's
head is therefore the CID bullet `/F2` (leftmost), and the gate refuses at the head.

### 1.1 Two further defects found while measuring

**(a) `mergeable()` crosses font resources.** A merged write puts the whole replacement
in the head fragment and clears every other fragment to empty. When the group spans
different fonts, the non-head fonts' glyphs are **silently discarded** — here the Arial
bullet and the Wingdings icon. The UI compounds it by claiming "33 fragments of Monaco"
when the group holds three faces. This is a data-loss bug independent of CID.

**(b) `program_of()` returns compressed bytes, so `ttf-parser` never parses a real font.**
`stream_bytes()` clones `Stream::content`, which for a Flate `FontFile2` is still
compressed. Measured: `/F3` content is 12,707 bytes and decompresses to 26,304; parsing
the raw bytes fails, parsing the decompressed ones yields 325 glyphs. Consequence: for
every real embedded font, `FontMetrics::resolve_with` falls through to `SimpleWidths`,
and `original_covers` returns `false`, forcing a MECH-A substitution where T11's "keep
the original" was supposed to win. Synthetic fixtures pass because they store the
program uncompressed — the fixtures are the only thing that has ever exercised that path.

## 2. What CID text actually is here

Both Type0 faces on this page are the **same Monaco program** as `/F3` (26,304 bytes,
byte-identical) with `/CIDToGIDMap /Identity`, and `/DW 1000` with no `/W` array.
Decompressed, the program maps every ASCII glyph in the line, including `2` and `-`.
Their `/ToUnicode` CMaps are deliberately minimal:

* `/F2` maps exactly one code, `<0087>` → U+2022 `•`.
* `/F6` maps exactly one code, `<0084>` → U+2013 `–`.
* `/F7` maps exactly one code, `<001F>` → U+F0E0 (a Wingdings private-use glyph).

So a CID run is editable when the replacement's characters can be turned into codes the
font can draw. Two independent routes exist, and they are not interchangeable:

1. **ToUnicode reverse lookup** — gives a *code* that already renders correctly, because
   the document says what it means. This is the only route that preserves semantics
   (e.g. `<001F>` really is the Wingdings bullet).
2. **Program `cmap` → GID** — valid only when `/CIDToGIDMap` is `/Identity`, because then
   CID *is* GID. It can encode text the CMap never named, at the cost of trusting the
   program's internal glyph order.

Route 2 is what makes `/F2` able to draw `Each…` at all. Route 1 is what makes an
existing glyph keep its meaning. **Route 1 must be tried first**, and a character found
by route 1 must not be re-encoded by route 2, or `•` would move from `<0087>` to
whatever GID ArialMT's `cmap` happens to assign META-BULLET.

## 3. Approach

### 3.1 A CID codec, not a special case

New module `editor/cid.rs` exposes one type:

```rust
pub struct CidFont {
    to_unicode: Option<ToUnicodeCMap>,   // route 1, and decoding
    program: Option<Vec<u8>>,            // decompressed; route 2 + width fallback
    identity_cid_to_gid: bool,
    default_width: u16,                  // /DW, default 1000
    widths: WidthTable,                  // /W, empty here
    cid_to_gid: Option<Vec<u16>>,        // when /CIDToGIDMap is a stream
}
```

* `decode(&[u8]) -> Option<String>` — unchanged semantics: `lopdf`'s
  `UnicodeMapEncoding`, so the picker and the write path agree.
* `encode(&str) -> Result<Vec<u8>, CidRefusal>` — per `char`: route 1, then route 2,
  then `CidRefusal::Uncoverable(ch)`.
* `advance(&[u8], size) -> Option<f32>` — `/W` then `/DW`; `None` only when neither the
  table nor `/DW` exists.

`encode` **must not** rely on `lopdf::Encoding::string_to_bytes`: it drops unmappable
characters silently (`textedit.rs:1972` already knows this and round-trips explicitly).
CID gets the same treatment, returning the offending character instead of a short string.

### 3.2 Gate: `simple-font` becomes `font-encoding`

`Gate::SimpleFont` refuses `!is_simple_font`. It becomes `Gate::FontEncoding`, which
refuses only when **neither** holds:

* a simple font (Type1 / TrueType / MMType1), or
* a Type0 whose encoding is Identity and which has a `/ToUnicode` (route 1 and decoding)
  and whose program parses (route 2, when route 1 misses).

A Type0 **without** `/ToUnicode` still refuses — its bytes cannot be decoded, so the picker
cannot show what it is editing. A Type0 whose `/CIDToGIDMap` is a stream, or is absent,
still refuses route 2 but may still be editable by route 1 alone.

The picker must pre-compute this (P2.4 §4), so the verdict is cheap and identical to the
write path's. Both call the same `CidFont::admissible`.

### 3.3 Merge must not cross faces, and must stay within one codec

`mergeable()` gains two conditions:

* `head.face == next.face` — the `/BaseFont` with its subset prefix stripped. Equality of
  *resource keys* would split a line over a producer re-subsets it; equality of `face`
  will not. `style_class` alone is too coarse: it maps `ArialMT`, `ABCDEE+Monaco` and
  `ABCDEE+Wingdings-Regular` all to `Helvetica`, which is precisely how the reported line
  became one group in the first place.
* `head.composable && next.composable` — the fragment's font can be a *write target* for
  arbitrary text. Face equality does not imply this: `/F3` and `/F6` here are the same
  Monaco program with different encodings, and a merged write through `F3`'s single-byte
  encoding would emit `F6`'s CID codes as unrelated glyphs.

A CID fragment is therefore never a merge target, even with another CID fragment of the
same font. That is a deliberate limit: a CMap covers a named subset of characters, so a
merged CID run would be offered for text it cannot draw. The fragments stay independently
editable — the reported line's `F3` body and its `F6` dash are each editable on their own,
which is the whole user-visible fix.

Rationale is §1.1(a): a merged write draws through one font, so a group spanning faces
re-renders the others' text in the head's glyphs. Honest grouping beats maximal grouping.

### 3.4 Width

`/DW 1000` on these fonts equals the 2048-unit program's 500-unit advance at 2 units per
1000, so `/DW` is accurate. The width gate therefore measures CID replacements from
`/W`/`/DW`, not from PDFium's box — same rule as T13's substitute path.

### 3.5 Undo

No new record type. A CID edit writes operand bytes and, at most, swaps a `Tf`, which
`ContentOperation` already describes. `/ToUnicode` is **never** rewritten: route 2 covers
program glyphs through `/Identity`, and mutating a shared document-wide CMap to suit one
edit is out of scope (it is the "embedding" half of C-4, deferred to P2.7.6).

## 4. Copy (option 3)

Refusals must name what is true and point at something that exists. `Add a text
annotation instead` is shown on a page with no text-annotation tool; the app's annotation
overlay is ink-only (P2-D8). Every refusal therefore ends in:

> `select a narrower range, or use the annotation tools to add a note`

and the toggle is renamed:

> **Substitute a standard font when this run's font cannot set the text** →
> **Substitute a standard font when a simple font cannot set the text (CID/Type0 runs keep
> their own font)**

`simple-font`/`font-encoding` messages name the concrete reason:

* `this text uses a CID/Type0 font whose glyphs cannot be reached without its embedded
  program; …`
* `this text uses a CID/Type0 font that publishes no /ToUnicode, so it cannot be read back
  reliably; …`

## 5. Tests

Fixture `cid_identity_monaco()` (testpdf.rs): Type0 + Identity-H, `/CIDToGIDMap /Identity`,
`/DW 1000`, a `/ToUnicode` mapping exactly the glyphs of one string, and the synthetic
program from `true_type_program_with_advance` stored **compressed** (so the decompression
fix is exercised).

| id | assertion |
|---|---|
| C1 | a CID run with a covering ToUnicode is `editable` |
| C2 | editing it round-trips: decode → replacement → decode equals the replacement |
| C3 | a character absent from both ToUnicode and program refuses `font-encoding`, naming it |
| C4 | a Type0 with no `/ToUnicode` refuses |
| C5 | `/CIDToGIDMap` not `/Identity` refuses route 2 but still allows route 1 |
| C6 | width comes from `/W`, then `/DW`; absent both is `None`, never a guess |
| C7 | `program_of` decompresses: a compressed `FontFile2` parses and its glyphs are covered |
| C8 | `mergeable` refuses two fragments with different `font_key` |
| C9 | a merged group is one font, so one encoding, so one `Tf` |
| C10 | the Maastricht page-4 line locates as ≥2 groups, the `/F3` one editable |

## 6. Out of scope

Rewriting `/ToUnicode`, embedding a new font program (P2.7.6), predefined CJK CMaps,
`/CIDToGIDMap` streams (refused, not approximated), Vertical writing, and reflow (P2.9).
