## 0. Problem statement (user-reported on 0.4.1, real PDF: "Maastricht Data Science Program" brochure)

**Symptom.** Picker row shows the line as merged (`online — combines 4 fragments`), but for the
line `5 month University level Data Sci|ence`, the merge chain broke: the tail `ence` became an
**orphan singleton**. Clicking anywhere on the line opened the orphan (`Replace ence with …`),
and the replacement "Hello from this world" **was written into the tail operand alone** —
the prefix kept, `ence` → `Hello from this world` (user screenshots, re-test 3).

**Two defects, both confirmed:**

1. **Chain-break orphan pairs to a line-sized box.** The orphan's only plausible box is the
   PDFium *line* box, so it inherited the line's width as its own identity/geometry, and every
   click on the line hits it (its box ≈ the line box).
2. **Width-quota hole (the dangerous one).** The gate-(d) old width came from the **paired box**
   (~300 pt of line), not the fragment's own span (~14 pt for `ence`). A ~110 pt replacement
   passed a quota that should have refused it. Gate O1's hard-refuse promise was bypassed by
   mis-measurement, not refusal.

## 1. Root causes (read from code at `8296508`)

- `mergeable()` gap uses `RawRun.advance`, which for subset fonts without AFM tables is
  **approximated** (`fragment_advance`) — an overestimate can end a chain that must continue,
  and inter-word gaps (~0.3–0.5 em in PowerPoint exports, where a space may be a kern shift
  rather than a glyph) exceed the 0.25 em constant.
- The 0.1 pt **absolute** size-equality rule can break chains over rendering-scale rounding.
- `pair_run()` has no box-vs-span sanity test, so a small run can claim a line-sized box
  (strong containment, baseline agreeing) and drag the line's width into gate (d).

## 2. New invariant T22 (and housekeeping amendments)

| # | Rule |
|----|------|
| **T22** | **A run's width-gate old width is its own measured span, never an inherited box width.** The span is measured with the font's in-file metrics (hmtx/AFM — the Stage-2 `O-ST2-2` machinery in `substitute.rs`, reused, not reimplemented). A paired box may supply the old width **only** when the pair is strong **and** box width ≤ span × 1.25 (box≈span). Otherwise the pair is *box-suspicious*: flagged weak, never merged, and its width quota = its own span; when no span is measurable at all, the run refuses rather than trusting the line box (safe direction). |

| Amended | Change |
|----|--------|
| `mergeable` gap | measured with **in-file metrics** (exact), not the approximation; gaps up to **0.5 em** are mergeable **only** when PDFium's reconstructed text contains a space at that boundary (space-kern case); overlap guard: gap < −0.05 em breaks the chain |
| size equality | relative: |Δsize| ≤ max(0.2 pt, 1 % of size), no longer a flat 0.1 pt |
| click targeting | click resolves to the **group-union box first**; fragment-level targeting only after explicit expand (P2.4.1 O-Pair-3's two levels honoured) |
