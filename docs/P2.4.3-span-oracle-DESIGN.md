## 2. New invariant T23 — the rendered page is the measurement oracle

**A run's span, and the gap between adjacent fragments, are measured from PDFium's rendered
character geometry, not from font metrics and not from approximations.** Font metrics and the
`fragment_advance` approximation demote to *fallbacks* when the char-grid measurement is
unavailable, in that order.

| # | Rule |
|----|------|
| **T23a (span)** | For a strongly paired run *or merged group*: locate the run's text in PDFium's char grid starting in the paired box's band (same baseline, x ≥ box.x0 − tolerance); the span is the union of that text's per-character rects. Per-fragment spans come from the walk within the group's range. Whitespace-normalisation must match PDFium's own reconstruction (same rule textlocate already uses for display text). |
| **T23b (gap)** | The gap between consecutive group-members = next fragment's span x0 − this fragment's span x1, both char-grid measured — exact, replacing `fragment_advance` in `mergeable()`. The space-kern conditional and overlap guard stay as frozen in P2.4.2. |
| **T23c (quota, amending T22)** | Quota preference order: (1) char-grid span; (2) font-metric span; (3) **strong pair whose box is the smallest containing PDFium box** may supply the quota — this restores 0.4.1's working `course`/`online` case; (4) refuse (unchanged message, gate `fits-width`). "Line-sized box" suspicion is decided against the char-grid span — so line-1's orphan is either correctly re-merged (T23b makes the chain whole) or correctly refused, but never silently free again. |
| **T23d (fallback honesty)** | When the char grid cannot be walked (no pair, unsearchable text), behaviour is exactly P2.4.2's — refusal with measured numbers when anything is measurable, the unmeasurable message otherwise. The over-refusal shrinks only as far as measurement allows; nothing is weakened. |

## 4. Boundaries

* One decode → mutate → encode pass, one save (T18); T4 revalidation unchanged; O1 message rules unchanged.
* MECH-A substitution semantics unchanged; **no** MECH-C re-typesetting in this round (noted as a
  future escape hatch for genuinely unpairable text; not designed here).
* No reflow, no CID re-encoding, no forms/OCR/merging (O3). Windows-only. No new dependencies —
  the PDFium binding in use already exposes per-character geometry; if it does not, STOP and
  report rather than adding one.
