# P2.4 Stage 2 — Font substitution & embedding (DESIGN, frozen pending sign-off)

Version 1.0 — 2026-10-04. Owner: GLM 5.3 Flash (design). Implementation after sign-off: Deepseek 4.1 Flash.
Supersedes nothing; EXTENDS `P2.4-DESIGN.md` (Stage 1, shipped). Stage gate per user ruling: one stage per design pass, no combined push.

## 0. Problem statement

Stage 1 edits only runs whose font is embedded-complete, non-subset, and simply encoded. Most
real PDFs embed **subsets** — the font file contains only the glyphs the original author used —
so Stage 1 refuses the majority of real-world edits with
`font-subset` / `encoding-round-trip`. Stage 2 converts those refusals into successful edits.

User ruling (2026-10-04, verbatim intent): Stage 2 = **"font embedding + subsetting (unlocks
most real PDFs)"**, delivered as real editing (no overlay), Windows only.

## 1. The dispatch fact that shapes everything

**The standard-14 fonts require no embedding and no glyph files.** `/BaseFont /Helvetica`,
`/Times-Roman`, `/Courier` (+ the 8 bold/italic variants) with `/Encoding /WinAnsiEncoding`
are guaranteed renderable by every conformant viewer — the font *program itself* doesn't exist
in the PDF. Widths are known constants (ISO 32000-1 Annex D / AFM metrics).

Consequence: a run whose original font is a subset can be edited by **switching it to a
standard-14 substitute** whose glyph coverage is total for Latin-1/WinAnsi. No font file
parsing, no embedding, no subsetting, no licensing question, tiny code. This covers the
dominant real case (Latin text in subset fonts).

True embedding (writing a real font program into the PDF) is needed only when:
- the replacement text needs glyphs **outside WinAnsi** (non-Latin scripts, typographic chars
  like ←→★), or
- fidelity demands keeping the original typeface (substituting Helvetica for a subset of
  Baskerville changes the document's look; that may be unacceptable).

Stage 2 therefore ships **two mechanisms, in order of preference**:
1. **MECH-A — substitute to standard-14** (no embedding): chosen by style-match from the
   original font name. Ships in Stage 2 core.
2. **MECH-B — embed a complete bundlable font** (Liberation Sans/Serif/Mono, OFL-licensed,
   embedding-permitted) for non-WinAnsi runs, with optional subsetting on save. Ships in
   Stage 2 extension, only if user confirms bundling a ~350 KB OFL font into the app.

## 2. Frozen invariants (T-numbers continue from P2.4)

| # | Invariant | Rationale |
|----|-----------|-----------|
| **T1** | *(unchanged)* lopdf is the ONLY writer. Font substitution and font embedding both persist through lopdf. PDFium never writes. | Two writers = corruption. |
| **T10** | **Substitution is never silent.** When MECH-A changes a run's font, the success path names the substitute: `"edited with Helvetica substituting ABCDEF+TimesNewRoman"`. | The user must know the file's appearance changed. |
| **T11** | **Glyph coverage is checked before substitution.** If the *original subset font actually contains* every needed glyph (rare, but happens), keep the original font. Substitution is the fallback, not the default. | Preserves fidelity whenever possible; substitution is visibly worse, so it must not fire unnecessarily. |
| **T12** | **No font parsing dependency without sign-off.** Coverage checks and TrueType metrics (via `ttf-parser`, pure Rust, zero deps) are the only proposed addition. If refused, fall back to lopdf-level dictionary inspection (subset prefix, /Encoding) + standard-14 AFM constants, and accept coarser gates. | Repo convention: no new deps silently. |
| **T13** | **The width gate (O1) is unchanged and enforced post-substitution.** Measured widths use the *final* font's metrics (substitute's AFM widths when MECH-A; embedded font's `hmtx` when MECH-B). Hard-refuse + both widths + annotation suggestion. | O1 ruling stands for all stages. |
| **T14** | **All Stage-1 gates still gate.** EncodingRoundTrip, RunMismatch, FitsWidth, SimpleFont (refusing CID-only runs remains until a later stage) apply to every edit, including MECH-A/B paths. | No stage weakens a safety gate. |
| **T15** | **Font resources added by MECH-A are document-local dictionary entries only** (`/Type /Font /Subtype /Type1 /BaseFont … /Encoding /WinAnsiEncoding`). No font-stream objects, no CMaps. | **T16** | **Edited pages' render caches invalidate by path+page (D6)** exactly as annotations do, and every stage-2 edit is undoable with the same coalescing/session rules as T7. | Consistency with P2 behaviour. |

## 3. Gate changes (v2)

| Gate | Stage 1 | Stage 2 |
|------|---------|---------|
| `font-subset` | refuse | MECH-A substitute (style-match) if WinAnsi-covered; **MECH-B** if not; refuse only if neither applies |
| `font-embedded` | refuse | unchanged refuse for *non-embedded non-standard* fonts (no metrics) |
| `encoding-round-trip` | refuse | still refuses CID/Identity-H byte-mapping (see §7 stage boundary) |
| `fits-width` | refuse w/ widths | refuse w/ widths of the FINAL font (T13) |
| `simple-font` | refuse | unchanged |

New named refusals: `GLYPHS_NOT_COVERABLE` (text needs glyphs neither original nor any
substitute can supply), `SUBSTITUTE_REFUSED` (user disabled substitution — see O-ST2-4).

## 4. Flows

**Edit flow v2** (replaces Stage 1 verdict logic in `textedit.rs`):
1. locate run (unchanged, `textlocate.rs`)
2. original gates (SimpleFont, EncodingRoundTrip, RunMismatch) — unmodified
3. **coverage check**: original font encodes every replacement codepoint?
   → yes: keep font, FitsWidth, edit
   → no: MECH-A pick substitute by style-match (family via name heuristic:
     serif→Times, mono→Courier, else Helvetica; weight/slant from name tokens Bold/Italic)
   → re-run FitsWidth against substitute metrics; refuse with widths if wider (O1)
4. mutate through lopdf: swap the run's `/Fx` resource reference to the substitute font dict
   (T15), remap bytes via substitute encoding, replace Tj operand bytes
5. persist (lopdf), invalidate cache, push undo (T16), return success + substitution note (T10)

**MECH-B flow** (extension): same, but step 4 embeds Liberation font program via lopdf
(`/Subtype /TrueType`, `/FirstChar /LastChar /Widths`, `/Encoding /WinAnsiEncoding`; or a
CID/Type0 dict for non-WinAnsi — deferred unless user confirms need), subsets on save if
O-ST2-5 confirmed.

## 5. Commands & UI deltas

- `edit_page_text` gains the v2 verdict logic + substitution note in its result.
- New optional command arg `substitute: bool` (default true per T10/T11 policy); UI exposes
  a toggle so users can demand STAGE-1-pure behaviour (refuse rather than substitute).
- Toast copy for the substitution note; no picker changes.
- No new commands required.

## 6. Fixtures & tests (gate matrix extension)

Extend the matrix (all via lopdf public API, no new deps):
- `subset-winansi.pdf` — subset font, replacement text INSIDE its glyph set (T11 keeps
  original font; asserts no substitution)
- `subset-winansi-escape.pdf` — replacement needs glyphs the subset lacks (assert MECH-A
  fires, font dict swapped, substitution note returned)
- `subset-wider-after-substitute.pdf` — substitute's metrics make text wider → assert
  FitsWidth refusal quotes substitute's measured widths (T13)
- `non-winansi-replacement.pdf` — replacement text with em-dash/arrow → with MECH-B absent,
  assert GLYPHS_NOT_COVERABLE refusal (doc for MECH-B's necessity)
- `style-match-cases.pdf` — Serif/Sans/Mono/Bold/Italic originals → assert each maps to the
  correct standard-14 family
Per existing rule: no gate without an automated test; CI Windows run is authoritative.

## 7. Stage boundaries (explicit non-goals for Stage 2)

- **CID/Identity-H re-encoding** stays refused (`encoding-round-trip`): mapping new text into
  an identity CMap is Stage 3-adjacent work with its own corruption surface.
- **Original-typeface fidelity for subsets** (i.e. "grow the subset") requires modifying the
  embedded font program — deferred to MECH-B if ever needed; MECH-A never touches glyph files.
- **Reflow** remains Stage 3 entirely.
- OCR/forms/signatures/creation/merge/macOS remain out (O3 unchanged).
