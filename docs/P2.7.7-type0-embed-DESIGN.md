## 1. Why this is a separate phase

P2.7.6 shipped MECH-B: a replacement outside CP1252 embeds a subset of a bundled face,
written as a **simple** `/TrueType` font with one-byte codes, `/Widths`, `/Differences`
and `/ToUnicode`. That covers the Helvetica/Times/Courier families and nothing else.

A document whose text is set in a CID-keyed font still cannot accept a replacement beyond
what the original face covers. `substitute.rs` refuses at `is_type0(font)`, and the user
sees `TYPE0_EMBED_UNIMPLEMENTED` (or `GLYPHS_NOT_COVERABLE` where coverage is the actual
limit). The refusal is honest. It is also a large class of real documents: anything from
InDesign or LaTeX with a subsetted identity-encoded face.

P2.7.6's machinery does **not** transfer directly, and pretending otherwise is how a phase
gets underestimated. A simple font is a flat code → glyph table. A Type0 font is a
two-level structure: `/Type0` → `/DescendantFonts` → `/CIDFontType2`, with a CMap deciding
how byte sequences become CIDs, and a separate `CIDToGIDMap` deciding how CIDs become
glyph ids.

## 2. What has to be written

1. **`/W` array** — CID-keyed widths. Not `/Widths`; the format is different, mixing
   ranges and explicit `[cid [w1 w2 ...]]` pairs. Getting the ranges wrong produces a
   font that parses and lays out incorrectly, which is the silent-wrongness shape.
2. **`CIDToGIDMap`** — either a stream mapping CID → glyph id or the name `/Identity`.
   `/Identity` is only correct when CIDs already *are* glyph ids, which is true for
   identity-encoded subsets and false in general.
3. **A `/CIDSystemInfo` triple** — Registry, Ordering, Supplement.
4. **A CMap** — reuse the original document's encoding CMap where the replacement can be
   given a CIDs slot in it; write an explicit CMap otherwise. Prefer reuse: a rewritten
   encoding is a chance to change how the *rest* of the run is read.
5. **Two-byte encoding of the replacement run** — the existing `decode_run_bytes` and
   `encode_simple` split is one-byte by construction. The Type0 path needs its own pair,
   and the round-trip gate must cover them.

## 3. Acceptance, to be written before implementation

The P2.7.6 matrix in `tests/embed_acceptance.rs` is the model. Rows must include:

- a Type0 run with a covered replacement, substitution allowed → embeds, and **PDFium
  renders and extracts it**;
- the same with substitution disallowed → `SUBSTITUTE_REFUSED`;
- a genuinely uncovered glyph in a Type0 run → `GLYPHS_NOT_COVERABLE`, not
  `TYPE0_EMBED_UNIMPLEMENTED`;
- a Type0 document not touched by the edit → byte-identical.

## 4. Standing constraints inherited from P2.7.6

- **Every guard mutation-verified with `scripts/mutate.sh`.** The mutant must be *caught*;
  a test that is green either way is a rehearsal (`AGENTS.md`, "Absence of evidence").
- **PDFium, not poppler, is the render authority.** A row that only poppler has seen is a
  coverage gap and must be recorded as one in the commit message.
- **A `/W` or `CIDToGIDMap` bug is silent.** It yields a plausible-looking PDF that draws
  glyphs at the wrong widths or wrong shapes. Tests must assert measured advances against
  the source face, not merely that the file parses.
